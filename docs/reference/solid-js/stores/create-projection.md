派生（プロジェクション）ストアを作成します — ストア版の `createMemo`
です。派生関数はミュータブルなドラフトを受け取り、その場で変更する
（正規の方法）か新しい値を返します。どちらの場合も結果は
`options.key`（デフォルト `"id"`）で前のドラフトと照合されるため、
存続するアイテムはプロキシの同一性を維持し、追加・削除されたアイテム
だけが作成・破棄されます。

プロジェクションされたストアを直接返します（セッターはなく、読み取り専用です）。

派生した計算の上にストアの構造共有・プロパティ単位の追跡が欲しいときに
使ってください。単純な読み取り専用の派生には `createMemo` の方が軽量です。

## インポート

```ts
import { createProjection } from "solid-js";
```

## 型シグネチャ

```ts
function createProjection<T extends object = {}>(
  fn: (draft: T) => void | T | Promise<void | T> | AsyncIterable<void | T>,
  seed: Partial<T> | Store<T>,
  options?: ProjectionOptions
): Store<T>;
```

## パラメータ

### `fn`

- **型:** `(draft: T) => void | T | Promise<void | T> | AsyncIterable<void | T>`

派生関数。ドラフトを受け取り、それを変更するか新しい値を返します。同期・非同期・`AsyncIterable` のいずれでも構いません。結果は `options.key` で照合されます。

### `seed`

- **型:** `Partial<T> | Store<T>`

初期内容であり、最初の派生が受け取るドラフトです。非同期の `fn` では、`seedLoadingValue` が設定されている場合にのみ、読み取り側は最初の結果の前にシードを見ます。設定がなければサスペンドします。

### `options`

- **型:** `ProjectionOptions`
- 省略可能

`key`（デフォルト `"id"`）、`seedLoadingValue`、`name`、`shallow`、`deferStream`、`ssrSource`。

## 戻り値

プロジェクションされたストア。セッターはありません。派生関数の入力を通じて書き込みます。

## 例

```ts
// Mutation form — update individual fields on the draft.
const summary = createProjection<{ total: number; active: number }>(
  draft => {
    draft.total = users().length;
    draft.active = users().filter(u => u.active).length;
  },
  { total: 0, active: 0 }
);

// Return form — produce a derived collection. Reconciled by `id`
// so each surviving user keeps the same store identity.
const activeUsers = createProjection<User[]>(
  () => allUsers().filter(u => u.active),
  []
);
```

**ハイドレーション:** `ProjectionOptions` は `ssrSource` フィールド
（`"server"` | `"hybrid"` | `"client"`）を受け付け、他のプリミティブと
同じクライアント対サーバーのトレードオフを提供します。

## 注意点

- セッターはありません。結果を変える方法は派生関数のリアクティブな入力です。
- 行が派生間で存続するのは `key` が一致した場合だけです。`id` を持たないデータには明示的な `key` か、位置による照合のための `key: null` が必要です。
- 非同期の派生では、`seedLoadingValue` が設定されていない限り最初の結果まで読み取り側はサスペンドします。設定されている場合はシードが先に表示されます。

## 関連する型

### `ProjectionOptions`

`createStore(fn, seed, options?)`、`createProjection(fn, seed, options?)`、
`createOptimisticStore(fn, seed, options?)` で作成される
派生・プロジェクションストアのオプション。

```ts
interface ProjectionOptions extends StoreOptions {
  key?: string | ((item: NonNullable<any>) => any) | null;
  seedLoadingValue?: boolean;
  deferStream?: boolean;
  ssrSource?: "server" | "hybrid" | "client";
};
```

#### `key`

- **型:** `string | ((item: NonNullable<any>) => any) | null`

照合の同一性のためのキープロパティ名または関数。`null` は位置でマージします

#### `seedLoadingValue`

- **型:** `boolean`

シードを最初にコミットされる値として扱います: ストアはシードの内容を持った
確定済みの状態で生まれ、派生の最初の実際の結果が届くまで表示されます。
その最初の結果が到着するまでの間、読み取りはどこでもシードを返します —
何も `<Loading>` バウンダリへサスペンドせず、更新も保留されず、
`isPending` は false のままです（シードが宣言によって答えるため、
初回ロード時の表示はデータ側に属します。例: シード内の
`skeleton: true` フィールド）。最初の結果が届くと（シードへ照合され）、
再フェッチは `isPending` が true の通常の保留中セマンティクスを使います。

`MemoOptions.loadingValue` のストア版。シードはすでにプレースホルダーの
形状を持っているため、このオプションが唯一必要なオプトインです。

#### `deferStream`

- **型:** `boolean`

このプリミティブの最初の値が解決するまで、SSR ストリームのフラッシュを
遅延します。周囲の `<Loading>` バウンダリにフォールバックを HTML へ
レンダーさせる代わりに、遅れて解決するソースがドキュメントを開いたままに
できます。サーバー専用。クライアントでは無視されます。

#### `ssrSource`

- **型:** `"server" | "hybrid" | "client"`

ハイドレーションポリシー。クライアントが使用する初期値と、
compute を再実行するかどうかを決定します。

- `"server"` *（デフォルト）*: クライアントは直列化されたサーバーの値を
  初期状態として使用します。compute は初期値のために再実行**されません**。
  直列化された結果が権威です。compute がサーバーで利用可能な入力から
  決定論的に求まる場合に選択してください。
- `"hybrid"`: クライアントは直列化されたサーバーの値を使い、その後
  compute を再実行して引き継ぎます。サーバーのデータとクライアント専用
  シグナル（例: ウィンドウサイズ、ユーザーロケール）を混ぜる compute に
  選択してください。
- `"client"`: サーバーの値を完全にスキップします。compute は
  ハイドレーションが完了するまで遅延され、その後初回マウント時と同様に
  実行されます。直列化が意味をなさないクライアント専用の状態に選択してください。
  compute 実行前の期間に何をレンダーするかは 2 つの形態で決まります:
  **bare**（構造的）——ソースはサーバー上で最終的な空白としてサスペンドし、
  最寄りの `<Loading>` バウンダリがフォールバックをレンダーして、
  その位置をクライアントに引き渡します。または **declared first value
  （宣言された初期値）**——シグナル系ソースの `loadingValue`
  （`loadingValue: undefined` も有効な宣言です）、ストア系ソースの
  `seedLoadingValue: true` で、バウンダリを介さず暫定データをレンダーします。
