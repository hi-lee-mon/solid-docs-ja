Proxy を基盤とする深くリアクティブなストアを作成します。読み取りは
アクセスされた各プロパティを追跡し、変更された部分だけが更新を
トリガーします。

ストアのプロパティが保持するのは **プレーンな値** であり、
アクセサーではありません。プロキシはプロパティごとに読み取りを
追跡済みなので、`() => state.foo` のように値をラップすると、
呼び出しても追跡 *されない* ゲッターができあがります。これは
リアクティビティのバグに見えますが、実際にはカテゴリーエラーです。
シグナル型の状態が必要なら、アクセサーを中にネストする
（`{ foo: () => signal() }`）のではなく、ストアのプロパティに
してください（`{ foo: 1 }`）。

セッターは **ドラフトを変更する** 関数を受け取ります。ドラフトを
その場で変更するのが標準的な使い方です。コールバックは新しい値を
返すこともできます: 配列はインデックスで置き換えられ（長さは
調整されます）、オブジェクトはトップレベルで浅く差分比較されます
（返された値に存在するキーは書き込まれ、欠けているキーは削除
されます）。変更が書きにくい形状 — もっとも多いのは `filter` で
要素を削除するケース — には return 形式を使ってください。セッターは
キーによるリコンシリエーションを **行いません**。それが必要なら
派生・プロジェクション形式（または `createProjection`）を
使ってください。

- **プレーン形式** — `createStore(initialValue, options?)`: 値を
  リアクティブなプロキシでラップします。
- **派生形式** — `createStore(fn, seed, options?)`: `fn(draft)`
  が中身を計算する *プロジェクションストア* です。`fn` は同期・
  非同期・`AsyncIterable` のいずれでも構いません。プロジェクションの
  結果は、安定した同一性を保つために `options.key`（デフォルト
  `"id"`）によって既存のストアとリコンシリエーションされます。

## 型シグネチャ

```ts
function createStore<T extends object = {}>(
  initialValue: T | Store<T>,
  options?: StoreOptions
): [get: Store<T>, set: StoreSetter<T>];
function createStore<T extends object = {}>(
  fn: (draft: T) => void | T | Promise<void | T> | AsyncIterable<void | T>,
  seed: Partial<T> | Store<T>,
  options?: ProjectionOptions
): [get: Store<T>, set: StoreSetter<T>];
```

## パラメータ

### `initialValue`

- **型:** `T | Store<T>`

ラップするプレーンなオブジェクトまたは配列。あるいは共有する既存のストア。

### `options`

- **型:** `StoreOptions | ProjectionOptions`
- 省略可能

プレーン形式では `name` と `shallow`。派生形式ではさらに `key`、`seedLoadingValue`、`deferStream`、`ssrSource` も受け取ります。

### `fn`

- **型:** `(draft: T) => void | T | Promise<void | T> | AsyncIterable<void | T>`

プロジェクション形式の派生関数。ドラフトを受け取り、それを変更するか新しい値を返します。同期・非同期・`AsyncIterable` のいずれでも構いません。

### `seed`

- **型:** `Partial<T> | Store<T>`

プロジェクションストアの初期内容であり、最初の派生が受け取るドラフトです。`fn` が非同期の場合、`seedLoadingValue` が設定されていれば、読み取り側は最初の結果が届く前にシードを見ます。設定されていなければサスペンドします。

## 戻り値

`[store: Store<T>, setStore: StoreSetter<T>]`

タプル。ストアは読み取った各プロパティを追跡する読み取り専用プロキシで、セッターは変更するためのドラフトを受け取り、それが返ると変更がコミットされます。

## 例

```ts
const [state, setState] = createStore({
  user: { name: "Ada", age: 36 },
  todos: [] as { id: string; text: string; done: boolean }[]
});

// Canonical: mutate the draft in place.
setState(s => { s.user.age = 37; });
setState(s => { s.todos.push({ id: "1", text: "x", done: false }); });

// Return form: reach for it when mutation is awkward.
setState(s => s.todos.filter(t => !t.done));               // remove items
setState(s => ({ ...s, user: { name: "Grace", age: 85 } })); // shallow replace
```

```ts
// Derived store — auto-fetches & reconciles by `id`.
const [users] = createStore(
  async () => fetch("/users").then(r => r.json()),
  [] as User[]
);
```

**ハイドレーション:** 派生形式は `ProjectionOptions` を受け取り、
`ssrSource` フィールド（`"server"` | `"hybrid"` | `"client"`）を
含みます。`ssrSource` オプションを参照してください。

## 注意点

- ストアのプロパティが保持するのはプレーンな値です。ストアの中にアクセサーをネストする（`{ count: () => count() }`）と、読み取っても追跡されません。
- セッターの外でストアを変更する（`state.items.push(x)`）のはリアクティブではありません。セッターのドラフトを通して書き込んでください。
- セッターはキーによるリコンシリエーションを行いません。配列を置き換えると行がインデックスで置き換わります。行の同一性を保つには `reconcile()` または派生形式を使ってください。
- プレーンなオブジェクト・配列・クラスインスタンスはラップされます。`Map` や `Date`、frozen オブジェクトなどの組み込みオブジェクトは生のまま格納されますが、それを保持するプロパティ自体は引き続き再代入を追跡します。

## 関連する型

### `ProjectionOptions`

`createStore(fn, seed, options?)`、`createProjection(fn, seed, options?)`、
`createOptimisticStore(fn, seed, options?)` で作成する派生・
プロジェクションストアのオプションです。

```ts
interface ProjectionOptions extends StoreOptions {
  key?: string | ((item: NonNullable<any>) => any) | null;
  seedLoadingValue?: boolean;
  deferStream?: boolean;
  ssrSource?: "server" | "hybrid" | "client";
};
```

#### `key`

- **型:** `string | ((item: NonNullable<any>) => any) | null`

リコンシリエーションの同一性を決めるキープロパティ名または関数。`null` を渡すと位置でマージします。

#### `seedLoadingValue`

- **型:** `boolean`

シードを最初のコミット済みの値として扱います: ストアはシードの
内容でコミット済みの状態として生成され、派生の最初の実際の答えが
届くまでそれが表示されます。最初の答えが処理中の間、読み取りは
どこでもシードを返します — `<Loading>` バウンダリにサスペンド
することも、更新が保留されることもなく、`isPending` は false の
ままです（シードは宣言によって答えを持ちます。初回ロード時の
affordance はデータ側に属します。たとえばシード内の
`skeleton: true` フィールドです）。最初の答えが届くと（シードに
リコンシリエーションされ）、それ以降の再取得は `isPending` が
true になる通常の pending セマンティクスに従います。

`MemoOptions.loadingValue` のストア版です。シードはすでに
プレースホルダーの形を持っているため、このオプションが唯一必要な
opt-in です。

#### `deferStream`

- **型:** `boolean`

このプリミティブの最初の値が解決するまで SSR ストリームのフラッシュを
遅延します。解決の遅いソースがドキュメントを開いたままにできるようにし、
周囲の `<Loading>` バウンダリがフォールバックを HTML にレンダーする
事態を避けます。サーバー専用で、クライアントでは無視されます。

#### `ssrSource`

- **型:** `"server" | "hybrid" | "client"`

ハイドレーションポリシー。クライアントが使う初期値と、計算を
再実行するかどうかを決めます。

- `"server"` *（デフォルト）*: クライアントはシリアライズされた
  サーバーの値を初期状態として使います。初期値のために計算は
  再実行 **されません** — シリアライズされた結果が正です。
  サーバーで利用可能な入力から計算が決定論的に求まる場合に
  選択してください。
- `"hybrid"`: クライアントはシリアライズされたサーバーの値を
  使い、その後で計算を再実行して引き継ぎます。サーバーの
  データとクライアント専用シグナル（ウィンドウサイズ、
  ユーザーロケールなど）を組み合わせる計算に選択してください。
- `"client"`: サーバーの値を完全にスキップします。計算は
  ハイドレーションが完了するまで遅延され、その後、初めて
  マウントされた場合と同様に実行されます。シリアライズが
  意味を持たないクライアント専用の状態に選択してください。
  計算前のウィンドウに何をレンダーするかは 2 つの形式で
  決まります: **bare**（構造的）— ソースはサーバー上で
  最終的な空白としてサスペンドし、最も近い `<Loading>`
  バウンダリがフォールバックをレンダーして、その位置を
  クライアントに引き渡します。もう 1 つは **宣言された
  最初の値** — シグナル系ソースでは `loadingValue`
  （`loadingValue: undefined` も有効な宣言です）、
  ストア系ソースでは `seedLoadingValue: true` — で、
  バウンダリを介さずに仮のデータをレンダーします。

### `ProjectionStoreReturn`

派生形式の `createStore(fn, seed, options?)` が返すタプルです。

```ts
type ProjectionStoreReturn<T> = [get: Store<T>, set: StoreSetter<T>];
```

### `StoreOptions`

すべてのストアプリミティブで共有されるオプションです。

```ts
interface StoreOptions {
  name?: string;
  shallow?: boolean;
};
```

#### `name`

- **型:** `string`

デバッグ名（開発モードのみ）

#### `shallow`

- **型:** `boolean`

単一レイヤーのストア: ルートキーはリアクティブ、値は参照ごと置き換わる生のレコードです。

### `StoreReturn`

プレーン形式の `createStore(initialValue, options?)` が返すタプルです。

```ts
type StoreReturn<T> = [get: Store<T>, set: StoreSetter<T>];
```

### `StoreSetter`

ストアのセッター。コールバックはストアの書き込み可能な
**ドラフト** を受け取ります。

- **その場で変更する（標準形）:** `s.foo = 1`、`s.list.push(x)`、
  `s.list.splice(i, 1)`。ほとんどの更新でこの形式がデフォルトです。
- **新しい値を返す:** 変更が書きにくい形状、もっとも多いのは
  要素の削除（`s => s.list.filter(...)`）に使います。配列は
  インデックスで置き換えられ（長さは調整されます）、オブジェクトは
  トップレベルで浅く差分比較されます（返された値に存在するキーは
  書き込まれ、欠けているキーは削除されます）。

セッターはキーによるリコンシリエーションを **行いません**。
配列全体の置き換えをまたいで残存する要素にストアの同一性を保た
せたい場合は、プロジェクション形式 — `createStore(fn, seed, { key })`
または `createProjection(fn, seed, { key })` — を使ってください。
その派生関数は返り値を `options.key` でリコンシリエーションします。

```ts
type StoreSetter<T> = (fn: (state: T) => T | void) => void;
```
