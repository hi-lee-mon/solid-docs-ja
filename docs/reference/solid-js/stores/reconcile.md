新しいデータをキーによって既存のストアにマージするストアセッターのコールバックを作成します。キーが一致する要素はストアの同一性を保つため、全体を置き換えても行は DOM・フォーカス・アニメーションの状態を維持します。追加・削除された要素だけが変化します。

## インポート

```ts
import { reconcile } from "solid-js";
```

## 型シグネチャ

```ts
function reconcile<T extends U, U>(
  value: T,
  key: string | ((item: NonNullable<any>) => any) | null = "id"
): (state: U) => T;
```

## パラメータ

### `value`

- **型:** `T`

新しいデータ。既存のストアを置き換えるのではなく、それにマージされます。

### `key`

- **型:** `string | ((item: NonNullable<any>) => any) | null`
- 省略可能

要素を識別するプロパティ名または関数。一致した要素はストアの同一性を保ちます。`null` を渡すと位置で照合します。

## 戻り値

セッターのコールバック。ストアのセッターに渡して使います: `setState(reconcile(next))`。

## 例

### サーバーからのリストで置き換えて行の同一性を保つ

```ts
const [todos, setTodos] = createStore<Todo[]>([]);

async function refetch() {
	const next = await fetch("/api/todos").then((r) => r.json());
	// Rows whose `id` matches keep their store proxy, so <For> keeps their DOM.
	setTodos(reconcile(next));
}
```

### 別の同一性フィールドを使う

```ts
setProducts(reconcile(nextProducts, "sku"));
setRows(reconcile(nextRows, (row) => row.region + row.year));
```

## 注意点

- ストアのルートがキー付きオブジェクトの場合、新しい値は同じキーを持つ必要があります。キーが異なると `Cannot reconcile states with different identity` をスローします。値全体をセッター経由で置き換えてください。
- キーを持たない要素は位置による照合にフォールバックし、どの階層でも型が変わるとそのサブツリーは置き換えられます。
