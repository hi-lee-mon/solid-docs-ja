**compute フェーズと effect フェーズを分離した**リアクティブなエフェクトを作成します。

- `compute(prev)` はリアクティブに実行されます。*リアクティブな読み取りはすべてここに記述してください*。
  戻り値は `effect` に渡され、次回実行時の新しい「前回の値」にもなります。
- `effect(next, prev?)` はキューがフラッシュされた後に、命令的に（追跡なしで）実行されます。
  *DOM への書き込み・fetch・ロギング・購読はここに記述してください。*
  クリーンアップ関数を返すことができ、その関数は次回のエフェクト実行前または破棄時に実行されます。

`effect` 内でのリアクティブな読み取りはこのエフェクトを再トリガー*しません*。
これは意図的な設計です。単一フェーズで追跡されるエフェクトが必要な場合は、
`createTrackedEffect` を使ってください（そこに記載のトレードオフを参照）。

compute または effect フェーズからスローされたエラーを捕捉するには、
プレーンな関数の代わりに `EffectBundle`（`{ effect, error }`）を渡します。

```ts
createEffect<T>(compute, effectFn | { effect, error }, options?: EffectOptions);
```

## インポート

```ts
import { createEffect } from "solid-js";
```

## 型シグネチャ

```ts
function createEffect<T>(
  compute: ComputeFunction<undefined | NoInfer<T>, T>,
  effectFn: EffectFunction<NoInfer<T>, T> | EffectBundle<NoInfer<T>, T>,
  options?: EffectOptions
): void;
```

## パラメータ

### `compute`

- **型:** `ComputeFunction<undefined | NoInfer<T>, T>`

前回の値を受け取り、計算に対して反応するために使われる新しい値を返す関数

### `effectFn`

- **型:** `EffectFunction<NoInfer<T>, T> | EffectBundle<NoInfer<T>, T>`

新しい値を受け取り、副作用を実行するために使われる関数（クリーンアップ関数を返せます）。または `effect` と `error` ハンドラーを持つ `EffectBundle`

### `options`

- **型:** `EffectOptions`
- 省略可能

`name`、`defer`、`schedule`、`transparent`、`deferStream`、`ssrSource`。

## 戻り値

なし。エフェクトは周囲のスコープに所有され、そのスコープとともに破棄されます。

## 例

```ts
const [count, setCount] = createSignal(0);

createEffect(
  () => count(),                  // compute: tracks `count`
  value => console.log(value)     // effect: side effect
);

setCount(1); // logs 1 after the next flush
```

```ts
createEffect(
  () => userId(),
  id => {
    const ctrl = new AbortController();
    fetch(`/users/${id}`, { signal: ctrl.signal });
    return () => ctrl.abort(); // cleanup before next run / disposal
  }
);
```

**ハイドレーション:** `EffectOptions` は `ssrSource` フィールド
（`"server"` | `"hybrid"` | `"client"`）を受け付けます。`ssrSource` オプションを参照してください。
`transparent: true` にするとエフェクトはハイドレーションから完全に見えなくなります。
ハイドレーション ID のスロットを消費せず、直列化されたサーバーの値を採用する代わりに
compute がライブで実行されます。サーバーが作成しなかったクライアント専用エフェクト向けです。

## 注意点

- 追跡されるのは `compute` フェーズだけです。`effectFn` 内の読み取りは購読しないため、`effectFn` でしかシグナルを読まないエフェクトは一度だけ実行されます。
- effect フェーズはキューがフラッシュされた後に実行されるため、同じ更新で書き込まれた DOM はすでに配置済みです。
- 同じエフェクトが追跡しているシグナルへの書き込みはループを作ります。代わりに `createMemo` で値を導出してください。
- サーバー上ではエフェクトは実行されません。

## 関連する型

### `ComputeFunction`

```ts
type ComputeFunction<Prev, Next extends Prev = Prev> = (
  v: Prev
) => PromiseLike<Next> | AsyncIterable<Next> | Next;
```

### `EffectBundle`

```ts
type EffectBundle<Prev, Next extends Prev = Prev> = {
  effect: EffectFunction<Prev, Next>;
  error: (err: unknown, cleanup: () => void) => void;
};
```

#### `effect`

- **型:** `EffectFunction<Prev, Next>`

#### `error`

- **型:** `(err: unknown, cleanup: () => void) => void`

compute フェーズのエラー（compute 関数がスローしたもの、または上流のソースから
届いたもの）を捕捉します。effect フェーズでのスローはここにはルーティングされません。
それらはユーザー自身の命令的コードであり、最寄りのエラーバウンダリへエスカレートします。

これは effect フェーズのエラー側の処理です: `effect` と同じキュー、
同じ命令的な書き込み可能スコープで実行され（シグナルへの書き込みは合法です）、
ユーザーコードがスローしたエラーを受け取り、確定した結果を観測します。
エフェクトフェーズの前に回復したエラーは代わりに `effect` 側を実行し、
保留された更新は `effect` と同様にそれを遅延させます。

### `EffectFunction`

```ts
type EffectFunction<Prev, Next extends Prev = Prev> = (
  v: Next,
  p?: Prev
) => (() => void) | void;
```

### `EffectOptions`

初回実行を遅延・スケジュールできるエフェクトプリミティブ（`createEffect`、`createRenderEffect`、`createReaction`）のオプション。

```ts
interface EffectOptions extends BaseEffectOptions {
  defer?: boolean;
  schedule?: boolean;
  sync?: boolean;
  transparent?: boolean;
  deferStream?: boolean;
  ssrSource?: "server" | "hybrid" | "client";
};
```

#### `defer`

- **型:** `boolean`

true の場合、初回のエフェクト実行を次の変更まで遅延します

#### `schedule`

- **型:** `boolean`

true の場合、初回のエフェクトコールバックを作成時に同期的に実行する代わりに、
エフェクトキューを通してエンキューします。初回実行を保留された更新に参加させます。
compute フェーズ中にいずれかのソースが `NotReadyError` をスローした場合、
保留中の処理が確定するまでコールバックは保留されます。

主に、非同期を考慮した初回マウントが必要なレンダーエフェクト（例: `render()` 内のルート
`insert()`）向けです。

#### `sync`

- **型:** `boolean`

高度なオプション。true の場合、compute 関数が同期的な値のみを返す
（`PromiseLike` / `AsyncIterable` を返さない）ことを表明します。
`recompute` 内の非同期形状プローブをスキップし、実行ごとにわずかな固定コストを削減します。
コンパイラの出力（`_$effect`）や、同期的な値を返すことが証明できるライブラリコードを
想定しています。`sync: true` のエフェクトから Promise や async iterable を返すのは
未定義動作です。その値はそのまま格納され、await されません。

#### `transparent`

- **型:** `boolean`

高度なオプション（統合ティア）。true の場合、エフェクトはハイドレーション ID
スキームから見えなくなります: 子スロットを消費する代わりに親の ID を継承し、
ハイドレーション中は直列化されたサーバーの値を採用する代わりに compute が
ライブで実行されます（初回実行はサーバーの決定に固定されません）。

**ハイドレーション中に作成されるクライアント専用エフェクト**——サーバーレンダーされた
対応物を持たないエフェクト（ルーターによるリンク状態の配線、スクロール復元など）——
向けです。サーバーが作成しなかった ID を消費するノードは、後続のすべての兄弟の
ハイドレーション ID をずらし、その後の直列化ルックアップやテンプレートのクレームを
外させます。`transparent` は、ハイドレーション状態で分岐する
（`if (hydrating) createEffect(...)`）方法のサポートされた代替でもあります。
分岐方式は初回実行が決めたものを凍結します: エフェクトを無条件に作成し、
ライブの状態を観測させてください。

SSR はこのオプションを無視します（サーバーサイドのエフェクトは常に自身の ID
スロットを割り当てます）。そのため、サーバーが作成しないエフェクトにのみ付けてください。
ハイドレーション以外では no-op です。

#### `deferStream`

- **型:** `boolean`

このプリミティブの最初の値が解決するまで、SSR ストリームのフラッシュを
遅延します。周囲の `<Loading>` バウンダリにフォールバックを HTML へ
レンダーさせる代わりに、遅れて解決するソースがドキュメントを開いたままにできます。
サーバー専用。クライアントでは無視されます。

#### `ssrSource`

- **型:** `"server" | "hybrid" | "client"`

ハイドレーションポリシー。クライアントが使用する初期値と、
compute を再実行するかどうかを決定します。

- `"server"` *（デフォルト）*: クライアントは直列化されたサーバーの値を
  初期状態として使用します。compute は初期値のために再実行**されません**。
  直列化された結果が権威です。compute がサーバーで利用可能な入力から
  決定論的に求まる場合に選択してください。
- `"hybrid"`: クライアントは直列化されたサーバーの値を使い、その後
  compute を再実行して引き継ぎます。サーバーのデータとクライアント専用
  シグナル（例: ウィンドウサイズ、ユーザーロケール）を混ぜる compute に
  選択してください。
- `"client"`: サーバーの値を完全にスキップします。compute は
  ハイドレーションが完了するまで遅延され、その後初回マウント時と同様に実行されます。
  直列化が意味をなさないクライアント専用の状態に選択してください。
  compute 実行前の期間に何をレンダーするかは 2 つの形態で決まります:
  **bare**（構造的）——ソースはサーバー上で最終的な空白としてサスペンドし、
  最寄りの `<Loading>` バウンダリがフォールバックをレンダーして、
  その位置をクライアントに引き渡します。または **declared first value
  （宣言された初期値）**——シグナル系ソースの `loadingValue`
  （`loadingValue: undefined` も有効な宣言です）、ストア系ソースの
  `seedLoadingValue: true` で、バウンダリを介さず暫定データをレンダーします。
