読み取り専用の派生したリアクティブなメモ化シグナルを作成します。

`compute(prev)` はリアクティブに実行されます。その内部でのリアクティブな
読み取りはすべて追跡され、戻り値がメモの現在値になります。
メモはキャッシュされます: 追跡しているソースのいずれかが
変更されたときだけ再計算されます。

```ts
const value = createMemo<T>(compute, options?: MemoOptions<T>);
```

## インポート

```ts
import { createMemo } from "solid-js";
```

## 型シグネチャ

```ts
function createMemo<T>(
  compute: ComputeFunction<NoInfer<T>, T>,
  options: MemoOptions<T> & { loadingValue: T }
): SourceAccessor<T>;
function createMemo<T>(
  compute: ComputeFunction<undefined | NoInfer<T>, T>,
  options?: MemoOptions<T>
): SourceAccessor<T>;
```

## パラメータ

### `compute`

- **型:** `ComputeFunction<T | undefined, T>`

前回の値を受け取り、新しい値を返します。内部の読み取りは追跡されます。Promise または `AsyncIterable` を返すとメモは非同期になり、最初の値が届くまで読み取り側はサスペンドします。

### `options`

- **型:** `MemoOptions<T>`
- 省略可能

`name`、`equals`、`lazy`、`loadingValue`、`deferStream`、`ssrSource`。下記の各メンバーを参照してください。

## 戻り値

読み取り専用のアクセサー。呼び出すとメモ化された値を読み取れます。読み取ると、周囲のスコープでメモが追跡されます。

## 例

```ts
const [first, setFirst] = createSignal("Ada");
const [last, setLast] = createSignal("Lovelace");

const fullName = createMemo(() => `${first()} ${last()}`);

fullName(); // "Ada Lovelace"
```

```ts
// Async memo — reads suspend inside <Loading>
const user = createMemo(async () => {
  const res = await fetch(`/users/${id()}`);
  return res.json();
});
```

**ハイドレーション:** `MemoOptions` は `ssrSource` フィールド
（`"server"` | `"hybrid"` | `"client"`）を受け付け、クライアントが使う初期値と
`compute` を再実行するかどうかを制御します。`ssrSource` オプションを参照してください。

## 注意点

- `compute` 内の読み取りは追跡されます。アクセサーを呼び出すコード内での読み取りは、メモではなくそのコード側で追跡されます。
- `compute` が Promise を返す場合、それが解決する前にアクセサーを読み取ると最寄りの `Loading` バウンダリまでサスペンドします。後続の更新は代わりに前回の値を保持します。
- メモは値のためのものです。副作用は `compute` ではなく `createEffect` に書いてください。

### `MemoOptions`

:::deep-dive[MemoOptions のメンバー]
`createMemo` で作成される読み取り専用メモのオプション。
書き込み可能なメモ（`createSignal(fn)` / `createOptimistic(fn)`）では
`SignalOptions` と組み合わせても使われます。

```ts
interface MemoOptions<T> {
  id?: string;
  name?: string;
  transparent?: boolean;
  equals?: false | ((prev: T, next: T) => boolean);
  unobserved?: () => void;
  lazy?: boolean;
  sync?: boolean;
  loadingValue?: T;
  deferStream?: boolean;
  ssrSource?: "server" | "hybrid" | "client";
};
```

**`id`** — `string`

オーナー階層のための安定した識別子

**`name`** — `string`

デバッグ名（開発モードのみ）

**`transparent`** — `boolean`

高度なオプション（統合ティア）。true の場合、メモはハイドレーション ID
スキームから見えなくなります: 子スロットを消費する代わりに親の ID を継承し、
ハイドレーション中は直列化されたサーバーの値を採用する代わりにライブで
計算します。サーバーレンダーされた対応物を持たないクライアント専用メモ向けです。
完全な意味論は `EffectOptions.transparent` を参照してください。
ハイドレーション以外では no-op です。

**`equals`** — `false | ((prev: T, next: T) => boolean)`

カスタムの等価性関数。または `false` を指定すると常に購読者へ通知します。
デフォルトは参照等価性（`isEqual`）です。値ベースの等価性には比較関数（例:
`(a, b) => a.id === b.id`）を渡すか、等価性に関係なく再計算のたびに通知するには
`false` を渡します。

**`unobserved`** — `() => void`

計算がすべての購読者を失ったときに呼び出されるコールバック

**`lazy`** — `boolean`

true の場合、初回の計算を値が最初に読み取られるまで遅延し、**さらに**
メモを自動破棄の対象にします。残っている購読者がいなくなると破棄され、
次の読み取り時に最初から再計算されます。アイドル期間をまたいで状態を保持
すべきでない、オンデマンド計算の値に使ってください。lazy でないオーナー付き
メモはオーナーの存続期間だけ生存し、自動破棄されません。

**`sync`** — `boolean`

高度なオプション。true の場合、compute 関数が同期的な値のみを返す
（`PromiseLike` / `AsyncIterable` を返さない）ことを表明します。
`recompute` 内の非同期形状プローブをスキップし、実行ごとにわずかな
固定コストを削減します。コンパイラの出力や、同期的な値を返すことが
証明できるライブラリコードを想定しています。`sync: true` のメモから
Promise や async iterable を返すのは未定義動作です。その値は
そのまま格納され、await されません。

**`loadingValue`** — `T`

最初にコミットされる値: メモが最初から持っている値で、compute の最初の
実際の結果が届くまで表示されます。その最初の結果が到着するまでの間、
メモはどこでも確定済みの値として読み取られます — 何も `<Loading>`
バウンダリへサスペンドせず、更新も保留されません（初回の到着待ちの処理は
ローディングクラスであり、バウンダリのフォールバックと同様です）。
`isPending(memo)` は **false** のままです: 宣言された初期値が宣言によって
その問いに答えるため、初回ロード時の表示は値自体から駆動されます（`null`
プレースホルダー、`skeleton: true` フィールドなど）。最初の結果が届くと、
ローディング値は系譜から永久に外れます: 再フェッチは通常の保留中
セマンティクスを使います（古い値が表示され、`isPending` が true になり、
ランタイムが更新を調整します）。正規のガードは
`data.skeleton || isPending(data)` で、その 2 つの項が 2 つの排他的な
状態をカバーします。

厳密に `T` 型として型付けされます: `null` / `undefined` をプレースホルダーに
使うには、メモの型でそれを宣言してください（例: `createMemo<User | null>(...)`）。
これですべての利用者が null になりうる期間を正直に見られます。
プレースホルダーが実データの代理となる形状のデータである場合、
真実を装わせるのではなく、その出自をデータにエンコードしてください
（例: `skeleton: true` フィールド）。

ローディング値は compute の最初の `prev` にもなるため、`prev` に基づく
メモはそこから畳み込まれます。

**`deferStream`** — `boolean`

このプリミティブの最初の値が解決するまで、SSR ストリームのフラッシュを
遅延します。周囲の `<Loading>` バウンダリにフォールバックを HTML へ
レンダーさせる代わりに、遅れて解決するソースがドキュメントを開いたままに
できます。サーバー専用。クライアントでは無視されます。

**`ssrSource`** — `"server" | "hybrid" | "client"`

ハイドレーションポリシー。クライアントが使用する初期値と、
compute を再実行するかどうかを決定します。

- `"server"` *（デフォルト）*: クライアントは直列化されたサーバーの値を
  初期状態として使用します。compute は初期値のために再実行**されません**。
  直列化された結果が権威です。compute がサーバーで利用可能な入力から
  決定論的に求まる場合に選択してください。
- `"hybrid"`: クライアントは直列化されたサーバーの値を使い、その後
  compute を再実行して引き継ぎます。サーバーのデータとクライアント専用
  シグナル（例: ウィンドウサイズ、ユーザーロケール）を混ぜる compute に
  選択してください。
- `"client"`: サーバーの値を完全にスキップします。compute は
  ハイドレーションが完了するまで遅延され、その後初回マウント時と同様に
  実行されます。直列化が意味をなさないクライアント専用の状態に選択してください。
  compute 実行前の期間に何をレンダーするかは 2 つの形態で決まります:
  **bare**（構造的）——ソースはサーバー上で最終的な空白としてサスペンドし、
  最寄りの `<Loading>` バウンダリがフォールバックをレンダーして、
  その位置をクライアントに引き渡します。または **declared first value
  （宣言された初期値）**——シグナル系ソースの `loadingValue`
  （`loadingValue: undefined` も有効な宣言です）、ストア系ソースの
  `seedLoadingValue: true` で、バウンダリを介さず暫定データをレンダーします。
:::
