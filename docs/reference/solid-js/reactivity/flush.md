保留中のリアクティブキューを同期的に処理するか、キューをドレインする前に
`fn` を同期的なフラッシュスコープで実行します。

リアクティブな更新は通常マイクロタスクキューにバッチされるため、連続した
複数の書き込みは 1 回の更新パスに集約されます。それらの書き込みの結果を
同期的に*観察*する必要があるときに `flush()` を呼びます。もっとも一般的なのは
テスト内ですが、命令的な統合コードの境界でも使います。書き込み自体に
マイクロタスクスケジューリングを回避させ、コールバックが戻ったときに
同期的にドレインさせたい場合はコールバックを渡してください。

## インポート

```ts
import { flush } from "solid-js";
```

## 型シグネチャ

```ts
function flush(): void;
function flush<T>(fn: () => T): T;
```

## パラメータ

### `fn`

- **型:** `() => T`

省略可能なコールバック。その中での書き込みはマイクロタスクスケジューリングを回避し、戻るとキューがドレインされます。

## 戻り値

`fn` が渡された場合は、その戻り値。

## 例

```ts
const [count, setCount] = createSignal(0);
const doubled = createMemo(() => count() * 2);

setCount(5);
flush();
expect(doubled()).toBe(10);

flush(() => setCount(6));
expect(doubled()).toBe(12);

// Nested flushes drain at each level:
flush(() => {
  setCount(7);
  flush(() => setCount(8)); // inner drain — effects fire here
  // outer continues with up-to-date state
});
```

## 注意点

- `action` 本体内や `onSettled` コールバック内で `flush()` を呼ばないでください。そこではキューはすでにドレイン中です。必要なら `queueMicrotask` で遅延してください。
- フラッシュしても非同期処理は解決しません。Promise を待っているメモは `flush()` 後も保留中のままです。
