## 関連する型

### `Dev`

dev 層です。devtools フック、グラフ走査、そして診断チャネルのコンソール側の窓口を提供します。dev ビルド（`__DEV__`）でのみ存在します。

```ts
interface Dev {
  hooks: DevHooks;
  getChildren: typeof getChildren;
  getSignals: typeof getSignals;
  getParent: typeof getParent;
  getSources: typeof getSources;
  getObservers: typeof getObservers;
  report(entry: DiagnosticEvent): void;
  setConsoleFooter(footer: ((event: DiagnosticEvent) => string | undefined) | undefined): void;
};
```

#### `hooks`

- **型:** `DevHooks`

#### `getChildren`

- **型:** `typeof getChildren`

#### `getSignals`

- **型:** `typeof getSignals`

#### `getParent`

- **型:** `typeof getParent`

#### `getSources`

- **型:** `typeof getSources`

#### `getObservers`

- **型:** `typeof getObservers`

#### `report`

- **型:** `void`

発行されたイベントのコンソール側の窓口です。`reportDiagnostic` を参照してください。

#### `setConsoleFooter`

- **型:** `void`

各診断コードの最初のコンソールレポートに付加されるコンソールフッターを登録します。より詳しいガイダンスへの導線です（たとえば solid-js は同梱の修復スキルを登録します）。
レポートとして現れるイベントでは同じコンソールエントリーの末尾行として表示され、スローされたエラーとして現れるイベントでは後続の行として付きます。
あるイベントに対して undefined を返すとフッターは抑制されます。undefined を渡すと登録が解除され、コードごとに一度だけ表示するための記録もリセットされます。

### `DiagnosticEvent`

```ts
interface DiagnosticEvent {
  sequence: number;
  code: DiagnosticCode;
  kind: DiagnosticKind;
  severity: DiagnosticSeverity;
  message: string;
  ownerId?: string;
  ownerName?: string;
  nodeName?: string;
  ownerPath?: string[];
  data?: Record<string, unknown>;
};
```

#### `sequence`

- **型:** `number`

#### `code`

- **型:** `DiagnosticCode`

#### `kind`

- **型:** `DiagnosticKind`

#### `severity`

- **型:** `DiagnosticSeverity`

#### `message`

- **型:** `string`

#### `ownerId`

- **型:** `string`

#### `ownerName`

- **型:** `string`

#### `nodeName`

- **型:** `string`

#### `ownerPath`

- **型:** `string[]`

イベントの対象を囲む、名前付きオーナーのルートから順のチェーンです。コンポーネントルートは `<Name>`、計算は `name` オプション（または `effect`/`computed` のデフォルト名）で表されます。例: `["<App>", "<TodoRow>", "effect"]`。
名前のないオーナー（プレーンなルート）はスキップされます。対象に名前付きオーナーがまったくない場合（トップレベルのスコープや、オーナーを持たないプリミティブ。それ自体が検出結果であることが多いです）は付きません。

#### `data`

- **型:** `Record<string, unknown>`

### `Diagnostics`

```ts
interface Diagnostics {
  subscribe(listener: DiagnosticListener): () => void;
  capture(): DiagnosticCapture;
  emit(
    event: Omit<DiagnosticEvent, "sequence">,
    subject?: DiagnosticSubject | null
  ): DiagnosticEvent;
};
```

#### `subscribe`

- **型:** `() => void`

#### `capture`

- **型:** `DiagnosticCapture`

#### `emit`

- **型:** `DiagnosticEvent`

リアクティブコアの外側からチャネルにイベントを記録します。ホストランタイムが自身の検出結果（ハイドレーションの不一致、サーバーレンダーの障害）を報告し、コンシューマーが 1 つのストリームとして見られるようにするためのものです。
`subject` は内部の発行箇所と同じ方法でイベントの位置を特定します。オーナーがシグナルのオーナーではないホストは、代わりにイベントの `ownerPath` を渡し、それがそのまま使われます。

### `DiagnosticSeverity`

`info` は参考情報の層です。表示する価値のある構造上の事実ですが、バグとは断定できません（たとえば深さ 2 の逐次フェッチチェーンは、本質的なデータ依存関係かもしれません）。
バジェットやアサーションを使うコンシューマーは、`info` を明示的に有効にしない限り `warn`/`error` だけを失敗として扱うべきです。

```ts
type DiagnosticSeverity = "info" | "warn" | "error";
```

### `DiagnosticSubject`

診断の対象となりうるすべてのものです。オーナー（ルート、computed、エフェクト）またはシグナルです。

```ts
type DiagnosticSubject = Owner | Signal<any> | Computed<any>;
```
