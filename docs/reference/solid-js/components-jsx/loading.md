サブツリー内の保留中の非同期読み取りが確定するまで `fallback` を
レンダーします。

データがまだ準備できていないためにスローする計算（`createMemo`、
`createSignal(fn)`、`createStore(fn)`、`lazy(...)` など）は、
最も近い外側の `<Loading>` に捕捉されます。バウンダリは、保留中の
読み取りがすべて解決するまで `fallback` に切り替え、その後
children をレンダーします。

省略可能な `on` prop はバウンダリの適用範囲を限定します。
バウンダリは、他のリアクティブソースへの書き込みによる更新では
以前のコンテンツを保持しつつ、保留中の処理を `isPending()` で
報告します。

`<Loading>` はデータに依存するスロットの周りに配置し、周囲の
シェルは含めないでください。レイアウトの枠（ヘッダー・ナビ・
フッター）をデータと同じバウンダリに入れると、再検証のたびに
画面全体が fallback に置き換わります。枠をバウンダリの外で
レンダーすれば、対象部分だけが切り替わり枠は安定したままに
なります。

## インポート

```ts
import { Loading } from "solid-js";
```

## 型シグネチャ

```ts
function Loading(props: {
  fallback?: JSX.Element;
  on?: any;
  children: JSX.Element;
}): JSX.Element;
```

## Props

### `fallback`

- **型:** `JSX.Element`
- 省略可能

サブツリー内の非同期読み取りに確定した値がない間にレンダーされます。

### `on`

- **型:** `any`
- 省略可能

アクセサーではなく値を渡します。値が変わり、かつ新しいコンテンツがまだ準備できていない場合、バウンダリは更新を保持せず再び fallback を表示します。

### `children`

- **型:** `JSX.Element`

このバウンダリが非同期読み取りを処理するサブツリー。

## 例

```tsx
const Profile = lazy(() => import("./Profile"));

<Loading fallback={<Spinner />}>
  <Profile />
</Loading>
```

```tsx
// Only show the fallback for updates caused by writes to `route`.
<Loading fallback={<Skeleton />} on={route}>
  <Page />
</Loading>
```

## 注意点

- バウンダリが fallback を表示するのは、内部の読み取りにまだ確定した値がない場合だけです。それ以降の更新では以前のコンテンツを保持します。再びプレースホルダーを表示すべきコンテンツには `on` を使います。
- `on` はアクセサーではなく値を比較します。`on={id}` ではなく `on={id()}` と渡してください。
- バウンダリはデータに依存するスロットの周りに配置し、安定させたいレイアウトの枠は含めないでください。
