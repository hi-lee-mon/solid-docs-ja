レンダーするコンポーネントをリアクティブなソースから取得する、安定したコンポーネントを作成します。ソースはコンポーネント・組み込み要素名・Promise・またはコンポーネントなしを返せます。

> `dynamic()` は正規の API です。安定したコンポーネント同一性を返し、`lazy()` やルーティングと組み合わせられます。

## インポート

```ts
import { dynamic } from "@solidjs/web";
```

## 型シグネチャ

```ts
function dynamic<T extends ValidComponent>(
  source: () => T | Promise<T> | null | undefined | false,
  options?: DynamicOptions
): Component<ComponentProps<T>>;
```

## パラメータ

### `source`

- **型:** `() => T | Promise<T> | null | undefined | false`

レンダーするコンポーネントを返すリアクティブな関数です。コンポーネント関数、組み込み要素名、それらの Promise、または何もレンダーしないことを示す falsy な値を返します。

### `options`

- **型:** `DynamicOptions`
- オプション

`deferStream` は、ソースが確定するまで SSR シェルを保留します。

## 戻り値

安定したコンポーネントです。`<Component />` としてレンダーし、対象コンポーネントの props を渡してください。

## 例

```tsx
const CurrentPage = dynamic(() => pages[route()]);

return <CurrentPage />;
```

## 注意点

- 返されるコンポーネントは安定しています。一度だけレンダーし、あとは `source` の変化に任せてください。レンダーパス内で作成するとサブツリーが再作成されます。

## 関連する型

### `DynamicOptions`

```ts
interface DynamicOptions {
  deferStream?: boolean;
  static?: boolean;
};
```

#### `deferStream`

- **型:** `boolean`

SSR のみ: ソースが確定するまでドキュメントの最初のフラッシュを保留し、
解決されたコンポーネントがバウンダリのフォールバックの後ろに
ストリーミングされるのではなく、シェル内にレンダーされるようにします。
`createMemo` の `deferStream` と同じ意味です。クライアントでは無視されます。

#### `static`

- **型:** `boolean`

ソースが変化し得ない場合: 追跡せず一度だけ呼び出し、インスタンスごとの
計算なしに結果をレンダーします（`dynamic` を参照）。ソースは同期的に
解決される必要があります。
