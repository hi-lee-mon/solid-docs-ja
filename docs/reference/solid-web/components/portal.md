children を DOM の別の場所にレンダーします（モーダルルート、
ツールチップ、`overflow: hidden` の祖先から逃れる必要があるレイヤー）。

`mount` を省略すると、ポータルは `document.body` にアタッチされます。
ポータルは親のリアクティブスコープに参加したままで、親が破棄されるときに
一緒に破棄されます。

ポータルはクライアント専用の島です: サーバーはそれに対して何もレンダーせず、
ハイドレーション下では children はハイドレーションが確定した後に新たに
レンダーされます。したがって、ポータル内の非同期読み取りはクライアントで
開始されます — サーバーでフェッチすべきデータはポータルの上に置きます
（レンダーではなく読み取りを巻き上げます）。また、ポータル内の非同期 UI
には独自の `<Loading>` バウンダリが必要です。

## インポート

```ts
import { Portal } from "@solidjs/web";
```

## 型シグネチャ

```ts
function Portal(props: { mount?: Element; children: JSX.Element }): JSX.Element;
```

## Props

### `mount`

- **型:** `Element`
- オプション

レンダー先の要素です。デフォルトは `document.body` です。

### `children`

- **型:** `JSX.Element`

マウント地点にレンダーするコンテンツです。

## 例

```tsx
<Portal mount={document.getElementById("modal-root")!}>
  <Dialog />
</Portal>
```

## 注意点

- サーバーはポータルに対して何もレンダーしません。children はハイドレーションが確定した後にクライアントでレンダーされます。
- ポータル内の非同期読み取りはクライアントで開始されます。ポータルの上でフェッチしてデータを渡し、内部の非同期コンテンツには独自の `Loading` バウンダリを与えてください。
- ポータルは親のリアクティブスコープを共有し、親とともに破棄されます。
