アンビエントなサーバーエラーフックを登録します。サーバーランタイムが処理または失敗するすべての障害について、エラーオブジェクトごとに一度だけ、その障害が検出された場所とともに呼び出されます。戻り値が指定された場合、クライアントが受け取る内容を置き換えます。

## インポート

```ts
import { configureServerErrors } from "@solidjs/web";
```

```ts
function configureServerErrors(config: ServerErrorsConfig): void;
```

## 関連型

### `ServerErrorContext`

サーバーエラーフックが検知する、サーバー側の障害が発生した場所です —
サーバーエントリの型に対するクライアント側のビューです（そちらの
`configureServerErrors` を参照）。`kind: "render"`: `fallback`/`client`/`failed`。
`kind: "server-function"`: `thrown`/`channel`。

```ts
interface ServerErrorContext extends Omit<ServerErrorSite, "event"> {
  event?: RequestEvent;
};
```

#### `event`

- **型:** `RequestEvent`

### `ServerErrorHook`

サーバーエラーフック（`configureServerErrors` を参照）: サーバー
ランタイムが処理または失敗するすべての障害について、エラーオブジェクト
ごとに一度だけ、検出された場所とともに呼び出されます。エラーの代わりに
クライアントが受け取るべき値を返します — フォールバックにレンダーされ、
ハイドレーション用にシリアライズされ、RPC エラーとして送信されます —
あるいはデフォルトポリシー（dev ビルド外では汎用 `Error`、dev ビルド内
ではエラーそのもの。`markSafeError` は引き続き素通りします）を使うなら
何も返しません。返された値は意図されたクライアント向けコンテンツとして
扱われ、再度サニタイズされません。通信経路を持たない
`handling: "failed"` では無視されます。

マッピングが届かない経路が一つあります。拒否された非同期ソースの
シリアライズされた拒否は、ソースが拒否された瞬間に、障害を検出する
バウンダリより先にエンコードされ、そこにはデフォルトポリシーの値が
載ります。ハイドレートするクライアントはバウンダリのレコードから
レンダーし、そちらにはマッピングが載ります。両者を一致させるために
エラーパスに追加のティックは入れられません。

```ts
type ServerErrorHook = (error: unknown, context: ServerErrorContext) => unknown | void;
```

### `ServerErrorsConfig`

```ts
interface ServerErrorsConfig {
  onError?: ServerErrorHook;
```

#### `onError`

- **型:** `ServerErrorHook`

### `ServerErrorSite`

サーバーエラーフックが検知する、サーバー障害が発生した場所です（`@solidjs/web` の `ServerErrorContext` を参照）。

```ts
interface ServerErrorSite {
  kind: "render" | "server-function";
  handling: "fallback" | "client" | "failed" | "serialize" | "thrown" | "channel";
  boundary?: string;
  ownerPath?: string[];
  boundaryPath?: string[];
  functionId?: string;
  direct?: boolean;
  event?: unknown;
};
```

#### `kind`

- **型:** `"render" | "server-function"`

#### `handling`

- **型:** `"fallback" | "client" | "failed" | "serialize" | "thrown" | "channel"`

#### `boundary`

- **型:** `string`

#### `ownerPath`

- **型:** `string[]`

エラーがスローされた場所 — エラーが脱出したオーナーチェーンをルートから順にたどるラベル。

#### `boundaryPath`

- **型:** `string[]`

エラーが検出された場所 — `boundary` で名付けられたバウンダリのチェーンをたどるラベル。

#### `functionId`

- **型:** `string`

#### `direct`

- **型:** `boolean`

#### `event`

- **型:** `unknown`

呼び出し元が保持している場合のリクエストイベント。それ以外の場合はリクエストスコープから読み取られます。
