リダイレクト `Response` を作成します（デフォルトはステータス 302）。`revalidate` を渡すとミューテーションが無効にしたキャッシュキーを指定でき、クライアントはリダイレクトに従った後にそれらを再フェッチします。

## 関連する型

### `Href`

```ts
interface Href {
  [HREF]: true | string;
  toString(): string;
};
```

#### `[HREF]`

- **型:** `true | string`

このブランドはチャネルも兼ねます。スロットが文字列を保持する場合、それは値の*論理*パス — インテグレーションの表示用レンダリング（例: ハッシュルーターの `#` プレフィックス）が適用される前の、ルーティング可能なパス名です。`redirect()` は文字列変換よりもこれを優先するため、Location ヘッダーはルーティング可能なパスを保持します。`toString()` は DOM 向けの表示 href のままです。`true` は、文字列表現がすでに論理パスである値をブランドします。

#### `toString`

- **型:** `string`

### `ResponseHelperInit`

レスポンスヘルパーが受け付ける `ResponseInit` に `revalidate` を加えたものです。

```ts
interface ResponseHelperInit extends ResponseInit {
  revalidate?: string | string[];
};
```

#### `revalidate`

- **型:** `string | string[]`

ミューテーションが無効にしたキャッシュキーで、`X-Revalidate` ヘッダーとして送信され、クライアント側のインテグレーションが適用します。宣言は3通り、スコープも3通りです。省略するとヘッダーは送信されず、ホストのデフォルトに従います（Solid Router はアクション後にすべてを再検証します。その規約のないルーターは自身が管理するものだけを再読み込みします）。空のリストは空のヘッダーを送信し、明示的に「何もしない」ことを意味します。`REVALIDATE_ALL`（`"*"`）は、ホストのデフォルトに関わらず全エントリーを対象にします。指定されたキーの照合方法（プレフィックス、名前空間など）は各インテグレーションの責務です。
