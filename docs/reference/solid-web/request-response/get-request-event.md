現在のサーバーレンダー、ミドルウェアチェーン、またはサーバー関数呼び出しに対応するリクエストイベントを返します。

## インポート

```ts
import { getRequestEvent } from "@solidjs/web";
```

## 型シグネチャ

```ts
function getRequestEvent(): RequestEvent | undefined;
```

## 例

```ts
const event = getRequestEvent();
const userId = event?.locals.userId;
```

## 関連する型

### `RequestEvent`

サーバーで利用できるリクエストごとのコンテキストです。受信した `Request` と、インテグレーションやミドルウェアが状態を格納できる `locals` バッグ（拡張可能な `RequestEventLocals` で型付けされる）を保持します。フレームワークは通常、この形をよりリッチなフィールドで拡張します（例: `response` ヘッド — `ResponseStub` を参照）。

```ts
interface RequestEvent {
  request: Request;
  locals: RequestEventLocals;
};
```

#### `request`

- **型:** `Request`

#### `locals`

- **型:** `RequestEventLocals`

### `RequestEventLocals`

`RequestEvent.locals` の型 — モジュール拡張（module augmentation）可能なインターフェイスで、アプリケーションはミドルウェアがイベントに格納する状態に型を付けられます。イベントを再エクスポートするパッケージ経由で拡張してください（インターフェイスの同一性は再エクスポートチェーンを通じて維持されます）:

```ts
declare module "@solidjs/web" {
  interface RequestEventLocals {
    user: User;
  }
}
```

インデックスシグネチャのおかげで、拡張しない使い方も寛容に動作します — `locals` はデフォルトで自由形式のバッグです。そのため拡張は、指定したキーに精度を追加するだけで、既存コードを妨げません。一方で、拡張されていないキーはエラーにならず `any` として読み取れます。これは意図的なトレードオフです（厳格な `locals` だけにすると、現在動作している型なしの書き込みがすべて壊れてしまいます）。

```ts
interface RequestEventLocals {
  [key: string | number | symbol]: any;
};
```

### `ResponseStub`

サーバーエントリーの `ResponseStub` を参照してください — インテグレーションがモジュール拡張を通じて `event.response` として公開する、ミュータブルなレスポンスヘッドの形です。

```ts
interface ResponseStub {
  status?: number;
  statusText?: string;
  headers: Headers;
  committed?: boolean;
};
```

#### `status`

- **型:** `number`

#### `statusText`

- **型:** `string`

#### `headers`

- **型:** `Headers`

#### `committed`

- **型:** `boolean`

このスタブからレスポンスヘッドが確定・送信された後に、インテグレーションが設定します（status/headers はそれ以降変更できません）。コンシューマーは、それ以降の書き込みとクリーンアップ時の取り消しを no-op として扱う必要があります。
