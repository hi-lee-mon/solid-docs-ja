レスポンスメタデータ（ステータス、ヘッダー、`revalidate`）を伴う値 — 素の戻り値では表現できないもののための仕組みです。プログレッシブエンハンスメントは見えないまま機能します。運ばれるレスポンスはプレーンな JSON ボディを保持するため、クライアントランタイムのないコンシューマー（JS なしのフォーム投稿、直接の HTTP）は本物の JSON を受け取り、インテグレーションは `value` を直接読みます — 再パースは不要です。

## 関連する型

### `ResponseEnvelope`

HTTP メタデータと値を組にするエンベロープです。`respond()` やサーバー関数の `transformResult` 実装（例: シングルフライトのペイロード）が生成します。HTTP ハンドラーは `response` のヘッダーと（リダイレクト以外の）ステータスを転送し、`value` をコーデックを通じてボディとしてエンコードします。クライアント専用のインテグレーションは `value` を直接読みます — 再パースは不要です。

```ts
interface ResponseEnvelope<T = unknown> {
  response: Response | undefined;
  value: T;
};
```

#### `response`

- **型:** `Response | undefined`

#### `value`

- **型:** `T`

### `ResponseHelperInit`

レスポンスヘルパーが受け付ける `ResponseInit` に `revalidate` を加えたものです。

```ts
interface ResponseHelperInit extends ResponseInit {
  revalidate?: string | string[];
};
```

#### `revalidate`

- **型:** `string | string[]`

ミューテーションが無効にしたキャッシュキーで、`X-Revalidate` ヘッダーとして送信され、クライアント側のインテグレーションが適用します。宣言は3通り、スコープも3通りです。省略するとヘッダーは送信されず、ホストのデフォルトに従います（Solid Router はアクション後にすべてを再検証します。その規約のないルーターは自身が管理するものだけを再読み込みします）。空のリストは空のヘッダーを送信し、明示的に「何もしない」ことを意味します。`REVALIDATE_ALL`（`"*"`）は、ホストのデフォルトに関わらず全エントリーを対象にします。指定されたキーの照合方法（プレフィックス、名前空間など）は各インテグレーションの責務です。

### `REVALIDATE_ALL`

全キャッシュの全エントリーを意味する予約済みの `revalidate` キーです。ホストに依存しない「すべて」の表記で（`Clear-Site-Data: "*"` がそうであるように）、ホストのデフォルトではなく本当に全件を意図する場合に使います。単独で指定します — 他のキーとの併記は拒否されます。「すべて、かつこれら」はスコープではなく誤りだからです。

```ts
const REVALIDATE_ALL: "*";
```
