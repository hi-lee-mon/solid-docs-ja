## 関連する型

### `CollectFlightDataHook`

シングルフライトのサーバーフックです: リクエストイベントと関数の結果を受け取り、戻り値と一緒にレスポンスへ折り畳むデータペイロードを（非同期でもよい）必要に応じて生成します。データの生成方法はプロトコルから見てブラックボックスです — データだけをレンダーしても、ルートのプリロードを実行しても、キャッシュを問い合わせても、統合が自由に選べます。ペイロードはコーデックでシリアライズ可能である必要があります。`undefined` を返すとレスポンスは変更されずに送られます（フックなしの呼び出しとバイト単位で同一です）。

`transformResult` の後に実行され、リクエストに `SINGLE_FLIGHT_HEADER` を付けて送信されたスクリプト経由の呼び出しのみが対象です。返された結果と、スローされた `Response` / `ResponseEnvelope` の制御フローシグナルの両方で動きます（プレーンなスローされたエラーは収集対象になりません。ボディを持つ素の `Response` 値も同様です — それらは呼び出し元のそのままのペイロードです）。エンベロープ化はハンドラーが担います: 提供されたデータはシングルフライトレスポンスヘッダーのもとで `{ value, data }` として送られます。収集の汎用的な部分はアウトカム上であらかじめ処理済みの状態で届きます（`targetUrl`、`revalidateKeys`、`foldedHeaders`）。フックが提供するのはデータ戦略だけです。

```ts
type CollectFlightDataHook = (
  event: ServerFunctionEvent,
  outcome: ServerFunctionOutcome
) => unknown | Promise<unknown>;
```

### `FlightDataConsumer`

クライアントでシングルフライトデータを受け取るコンシューマーです: `data` は統合が生成したペイロード（プロトコルからは不透明）、`context` はエンベロープのメタデータを保持します。レスポンスが統合メタデータ（リダイレクト、再検証キー）を運んだがサーバーがこのソース向けのスライスを折り畳まなかった場合、`data` は `undefined` です — メタデータを適用するためにコンシューマーはそれでも実行されます。非同期のコンシューマーは関数の値が呼び出し元へ返される前に await されるため、先にキャッシュへ値を入れられます。

```ts
type FlightDataConsumer<D = unknown> = (
  data: D | undefined,
  context: FlightDataContext
) => void | Promise<void>;
```

### `FlightDataContext`

シングルフライトデータと一緒に届くエンベロープコンテキストです: トランスポートレスポンスで、そのヘッダーは統合メタデータ（データ付きリダイレクトのためのリダイレクト情報、`X-Revalidate` キー）とステータスを保持します。ボディはすでに消費済みです — `data` と `value` はここからではなく配信結果から読んでください。

```ts
interface FlightDataContext {
  response: Response;
};
```

#### `response`

- **型:** `Response`

データが載って届いた HTTP レスポンスです（メタデータのみ）。

### `ServerFunctionOutcome`

シングルフライトフックから見た、サーバー関数呼び出しの結果です — コア側が特定の方式を仮定せずに済むよう、あらゆるデータ生成戦略に十分なコンテキストを提供します。

```ts
interface ServerFunctionOutcome {
  id: string;
  value: unknown;
  response: Response | undefined;
  request: Request;
  thrown: boolean;
  targetUrl: string | undefined;
  revalidateKeys: string[] | undefined;
  foldedHeaders: Headers;
};
```

#### `id`

- **型:** `string`

実行された関数の、ビルド間で安定した id です。

#### `value`

- **型:** `unknown`

呼び出し元が受け取る値です: 通常の結果では生の戻り値、`ResponseEnvelope` では展開された `value`、ボディを持たない制御フロー用 `Response`（リダイレクト / リロード）では `null` です。

#### `response`

- **型:** `Response | undefined`

結果の HTTP メタデータを保持する `Response` です（返された / スローされた `Response`、または `ResponseEnvelope` 由来のものがある場合）。データ付きリダイレクトではここの `Location` を読みます — データは遷移先のルートを記述するべきです — `X-Revalidate` は無効化されたキーを示します。プレーンな値の場合は undefined です。

#### `request`

- **型:** `Request`

変更されていない元の HTTP リクエストです: クライアント統合が送ったヘッダー（リファラー、カスタムルートコンテキスト）はここに載っており、フックが読み取れます — コアはそれらに意味を与えません。

#### `thrown`

- **型:** `boolean`

結果が返されたのではなくスローされたかどうかです。

#### `targetUrl`

- **型:** `string | undefined`

ミューテーション後にクライアントが表示する URL です — アウトカムがリダイレクト `Location` を持つ場合はそれ（ブラウザと同様にリクエスト URL に対して解決）、それ以外では遷移元のページです。利用できる referer がない場合（ブラウザ以外の呼び出し元にはデータを生成する対象のページがない）や、アプリのオリジンを外れるリダイレクトの場合は undefined です: これが undefined のときはデータを生成しません。

#### `revalidateKeys`

- **型:** `string[] | undefined`

アウトカムの `X-Revalidate` キーを分割したもの — ミューテーションが宣言した無効化スコープです。アウトカムがキーを持たない場合は undefined（その場合、統合は通常ターゲットのすべてを収集します）。空の宣言（何もなし）では `[""]`、`REVALIDATE_ALL` では `["*"]` となり、宣言どおりに渡されるため、コレクターは「すべて」と個別キーを区別できます。

#### `foldedHeaders`

- **型:** `Headers`

ミューテーションの Cookie 効果を適用済みのリクエストヘッダーです: まずイベントレスポンスの `Set-Cookie`（呼び出し中に設定されたもの）、次にアウトカム自身のもの（例: `redirect(to, { headers })`）が適用され、競合時は後のものが優先され、削除も反映されます。再実行される読み取りがミューテーション後の Cookie 状態を観測できるよう、データ収集用のリクエストはこれらから構築してください。

### `SingleFlightPayload`

シングルフライトレスポンス（`SINGLE_FLIGHT_HEADER` が付いたレスポンス）の標準化されたボディです: 関数の戻り値 `value` と統合が生成した `data` ペイロードが、HTTP ハンドラーによって 1 回の往復に折り畳まれます。パススルーレスポンスを自分でデコードする統合（登録されたコンシューマーなし）は、`decodeResponse` からこの形を受け取ります。トップレベルはプロトコル用に予約されています — 統合ペイロードはすべて `data` の下に置かれ、エンベロープはソース id をキーにします（名前なし登録のスライスは予約済み id `"true"` の下に載ります）。各スライスはコーデックでシリアライズ可能な任意の値です。

```ts
interface SingleFlightPayload<T = unknown, D = unknown> {
  value: T;
  data: D;
};
```

#### `value`

- **型:** `T`

サーバー関数の戻り値（またはスローされた値）です。

#### `data`

- **型:** `D`

統合が生成したデータペイロードで、ソース id をキーにします。
