async iterable が時間とともに変化する1つの値を表すサーバー関数を宣言します。ブラウザは一時的に失敗したストリームを再接続し、`onstatus` を通じて接続状態を公開します。

> ソースの契約、再接続の動作、リアクティブな消費については[読み取り・ストリーム・ライブデータ](/docs/building-apps/server-functions/reads-and-live-data.md#declare-a-live-source)を参照してください。

## インポート

```ts
import { live } from "@solidjs/web/server-functions";
```

## 型シグネチャ

```ts
function live<A extends readonly any[], R>(
  fn: (...args: A) => R
): LiveServerFunction<A, Awaited<R>>;
```

## パラメータ

### `fn`

- **型:** `(...args: A) => R`

## 例

```ts
export const stockPrice = live(async function* (symbol: string) {
	"use server";
	for await (const tick of market.subscribe(symbol)) {
		yield tick.price;
	}
});
```

## 関連する型

### `LiveServerFunction`

```ts
interface LiveServerFunction<A extends readonly any[] = any[], R = any> {
  (...args: A): LiveSource<R>;
  readonly id: string;
  readonly url: string;
};
```

#### `id`

- **型:** `string`

ビルド間で安定した関数 id です（クライアントビルドとサーバービルドで同一）。

#### `url`

- **型:** `string`

HTTP 経由でこの関数を直接呼び出す URL です。

### `LiveSource`

ライブ呼び出しの応答です: ソースの iterable に加えて、再接続ループが値ストリームから消してしまう通信上の事実を伝える、オプションの `onstatus` サイドチャネルを持ちます — 成功した（再）接続ごとに `"connected"`、接続後の一時的な切断ごとに `"reconnecting"`（エラー付き）、ソースが完了するかコンシューマーが終了したときに `"closed"` を通知します — 終了がリトライではなく即座に失敗する確定的な拒否（4xx）だった場合はエラー付きです。

```ts
type LiveSource<R> = R & {
  onstatus?: (state: LiveSourceStatus, error?: unknown) => void;
};
```

### `LiveSourceStatus`

ライブ呼び出しの iterable が報告できる通信状態の遷移です。

```ts
type LiveSourceStatus = "connected" | "reconnecting" | "closed";
```
