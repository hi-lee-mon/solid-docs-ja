## 関連する型

### `FlashSubmission`

クライアントランタイムなしで行われた呼び出しの結果が、フラッシュクッキーに載る際の形です: 何が送信され、どこへ送られ、何が返ってきたかを保持します。`result` と `error` は排他的です — スローされた結果は `error` に、返された結果は `result` に入ります — スクリプト経由の呼び出しが見る分割と同じ構造です。

```ts
interface FlashSubmission {
  input: any[];
  url: string;
  result?: any;
  error?: any;
  truncated?: boolean;
};
```

#### `input`

- **型:** `any[]`

呼び出しに使われた引数です（ファイルは除外されます）。

#### `url`

- **型:** `string`

呼び出しの URL です: バインドされていない関数のベース — サーバー関数リクエストのパス名（`<endpoint>/<id>`）で、`.with()` でバインドされたフォームの action が持つ `?args=` クエリ（やその他のクエリ装飾）は含みません。スクリプト経路が送信の URL として記録するものと一致するため、統合は同じ `s.url === fn.base` の判定でフラッシュ送信とスクリプト送信を照合できます。バインドされた引数は代わりに `input` に届き、スクリプト呼び出しとまったく同じように先頭に追加されます。

#### `result`

- **型:** `any`

呼び出しが値を返した場合の、その戻り値です。

#### `error`

- **型:** `any`

呼び出しがスローした場合の、その値です。

#### `truncated`

- **型:** `boolean`

結果がクッキーの 4 KB 上限を超え、収まるように縮退した場合に設定されます（#3137）: 入力のエコーは削除され、`result` / `error` は完全な値ではなく、上限付きのプレフィックス — あるいは結果フラグ `true` のみ — を持つことがあります。送信結果は依然として「何が」「どこで」起きたかを伝えます。統合は値を再生するのではなく、「成功（結果が大きすぎて表示できません）」として描画すべきです。

### `NoJSHandlerOptions`

`createNoJSHandler` のオプションです。

```ts
interface NoJSHandlerOptions {
  base?: string;
};
```

#### `base`

- **型:** `string`

アプリのマウントパスです。相対的なリダイレクト `Location` を解決するために使います。
