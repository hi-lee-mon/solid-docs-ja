## 関連する型

### `HandleServerFunctionOptions`

`handleServerFunctionRequest` にフレームワークのポリシーを重ねるフックです。
すべて省略可能です — 素のハンドラーは単独でディスパッチ、イベントのスコーピング、結果のエンコードを行います。

```ts
interface HandleServerFunctionOptions {
  createEvent?(request: Request): ServerFunctionEvent;
  provideEvent?<T>(event: ServerFunctionEvent, fn: () => T): T;
  wrapInvocation?: WrapInvocationHook;
  onError?: ServerErrorHook;
  transformResult?(
    event: ServerFunctionEvent,
    result: unknown,
    context: {
      id: string;
      args: unknown[];
      request: Request;
      thrown?: boolean;
    }
  ): unknown | ResponseEnvelope | Promise<unknown | ResponseEnvelope>;
  collectFlightData?: CollectFlightDataHook;
  transformFlightResult?(
    event: ServerFunctionEvent,
    outcome: { value: unknown; data: unknown },
    context: { id: string; args: unknown[]; request: Request }
  ): Response | undefined | Promise<Response | undefined>;
  handleNoJS?(
    result: unknown,
    request: Request,
    args: unknown[],
    thrown?: boolean
  ): Response | Promise<Response>;
  csrf?: boolean | ServerFunctionCSRFOptions;
  codec?: JSONCodecOptions;
  bodySizeLimit?: number;
  maxArguments?: number;
};
```

#### `createEvent`

- **型:** `ServerFunctionEvent`

呼び出しが実行されるリクエストイベントを構築します（デフォルト: 素の
`{ request, locals: {} }`）。統合は、よりリッチなイベント
（クッキー、レスポンスヘルパー、プラットフォームハンドル）を提供します。

`request` は標準の形をした `Request` — url、method、headers、
signal、読み取り可能なボディ — であり、それ以上のものではありません。`bodySizeLimit`
を強制すると、ランタイムがホストのストリームとデコーダーの間に入るため、
ここに渡されるオブジェクトはランタイムが再構築したものである場合があります。受信オブジェクトの
ホスト固有フィールド（`request.cf`、srvx の `runtime`、`ip`、
`waitUntil`）は引き継がれません。ホストはハンドラーを呼ぶ際、クロージャ内に
自分自身のリクエストを持っています: プラットフォームハンドルはそこから読み、
`request` 経由ではなくイベント（`locals`）に載せてください。

#### `provideEvent`

- **型:** `T`

このハンドラーに対して設定済みのイベントプロバイダーを上書きします — `provideEvent` 設定オプションと同じ契約です。

#### `wrapInvocation`

- **型:** `WrapInvocationHook`

このハンドラーに対して設定済みの呼び出しごとのラップを上書きします — `wrapInvocation` 設定オプション（
`WrapInvocationHook` を参照）と同じ契約ですが、こちらはエントリー専用です: リクエストが指し示した呼び出しだけを正確に
ラップします。ディスパッチされた本体が行うネストされた直接サーバー関数呼び出しは、これでは再ラップされません — それらは設定済みフックのみを参照します。そのフックはアンビエントで、すべての直接呼び出しをラップします
（リクエスト単位のオプションは直接 SSR 呼び出しを見られません）。すべてのホップをカバーしなければならないポリシーは、ここではなく `configureServerFunctionsServer` の
`wrapInvocation` に置いてください。

#### `onError`

- **型:** `ServerErrorHook`

このリクエストのサーバーエラーフックで、`configureServerErrors` のものより先に呼ばれます（
`@solidjs/web` の `ServerErrorHook` を参照）: 関数のスロー
（`handling: "thrown"`）と、結果グラフを抜けてきた失敗
（`"channel"`）を、エラーごとに1回、通信ポリシーが適用される前に受け取ります。
`wrapInvocation` と同様にエントリー専用です: 本体がレンダー中に行う直接呼び出しは、アンビエントのフックを通じて報告されます。

#### `transformResult`

- **型:** `unknown | ResponseEnvelope | Promise<unknown | ResponseEnvelope>`

エンコード前に関数の結果を観察または置き換えます —
レスポンスメタデータポリシー（ヘッダー、ステータス、
差し替え結果）の拡張ポイントです。返された結果とスローされた結果の両方で実行されます
（`context.thrown` で区別します）。コンテキストは呼び出しの
識別情報 — 関数 `id` と実装が呼ばれた際のパース済み `args` — を保持し、直接呼び出しのミラー
（`transformDirectResult`）と一致するため、呼び出しで状態をキーイングするポリシーはどちらのディスパッチ経路でも機能します。
`context.request` はスクリプト経由の呼び出し（
`/data/` アドレス）とベアアドレスの呼び出しを区別します。そのまま通すには結果を
変更せずに返し、HTTP メタデータと構造化ペイロードを送るには `ResponseEnvelope`（
コアエントリ経由で公開）を返します。`collectFlightData` より前に実行されるため、flight フックは変換後の
結果を見ます — レスポンスにデータを折り込むにはこちらではなく `collectFlightData` を使ってください。

#### `collectFlightData`

- **型:** `CollectFlightDataHook`

このハンドラーに対して設定済みのシングルフライトフックを上書きします — `collectFlightData` 設定オプション（
`CollectFlightDataHook` を参照）と同じ契約です。

#### `transformFlightResult`

- **型:** `Response | undefined | Promise<Response | undefined>`

このハンドラーに対して設定済みのシングルフライト集約ポリシーを上書きします — `transformFlightResult` 設定オプションと同じ契約です。

#### `handleNoJS`

- **型:** `Response | Promise<Response>`

クライアントランタイムなしで行われた呼び出し（ベアアドレスへのもの — no-JS フォーム投稿、直接 HTTP）のレスポンスを構築します。（変換済みの）結果、リクエスト、デコード済み引数を受け取ります。結果が返されたのではなくスローされた場合、`thrown` が設定されます。

設定済みフックを上書きします。そのフックは、ブラウザのフォーム投稿に適用される組み込みの
`createNoJSHandler()` をさらに上書きします。ベアアドレスの他の呼び出し元には、通常のシリアライズ済みレスポンスが返ります。

#### `csrf`

- **型:** `boolean | ServerFunctionCSRFOptions`

このハンドラーの同一オリジン保護を上書きします。別の信頼できる層がエンドポイントを保護している場合のみ `false` に設定してください。

#### `codec`

- **型:** `JSONCodecOptions`

このハンドラーに対して設定済みのコーデックオプションを上書きします。

#### `bodySizeLimit`

- **型:** `number`

このハンドラーに対して設定済みの引数ペイロード上限を上書きします（
`ServerFunctionsServerConfig.bodySizeLimit` を参照）。

#### `maxArguments`

- **型:** `number`

このハンドラーに対して設定済みの引数数上限を上書きします（
`ServerFunctionsServerConfig.maxArguments` を参照）。

### `ServerFunctionCSRFOptions`

サーバー関数リクエストの同一オリジン検証オプションです。

```ts
interface ServerFunctionCSRFOptions {
  origin?: ServerFunctionOriginMatcher;
  allowRequestsWithoutOriginCheck?: boolean;
  protectDeclaredReads?: boolean;
};
```

#### `origin`

- **型:** `ServerFunctionOriginMatcher`

期待される公開オリジンです。デフォルトは受信リクエスト URL のオリジンです。
関数はマルチテナントホスト向けにオリジンを動的に検証できます。

#### `allowRequestsWithoutOriginCheck`

- **型:** `boolean`

`Sec-Fetch-Site`、`Origin`、`Referer` のいずれもないリクエストを許可します。
クロスオリジンのメタデータは依然として拒否されます。

#### `protectDeclaredReads`

- **型:** `boolean`

GET 宣言された読み取りにもオリジンゲートを適用します。デフォルトでは
宣言済み読み取りに対してゲートはスキップされます: 同一オリジンポリシーがすでに
クロスサイトの呼び出し元によるレスポンスの読み取りを防いでおり、ゲートの `Vary` は `GET` ヘルパーが有効化するために存在する共有キャッシュエントリを分断します
（Vary を無視する CDN では汚染します）（#3071）。このスキップが依拠する前提は `GET()` の安全性契約です — 宣言済み読み取りはどのオリジンから実行しても安全です（#3114）。共有キャッシュに依存しないデプロイでは、これを有効にして読み取りにもゲートをかけられます。

### `ServerFunctionEvent`

サーバー関数呼び出しが実行されるリクエストイベントです: 基本の
`RequestEvent`（request + locals）に `serverOnly` が追加されたもので、呼び出しがプロセス内 SSR 呼び出しで結果がクライアントへシリアライズされない場合に設定されます。

```ts
interface ServerFunctionEvent extends RequestEvent {
  serverOnly?: boolean;
};
```

#### `serverOnly`

- **型:** `boolean`

### `ServerFunctionsServerConfig`

`configureServerFunctionsServer` のオプションです。

```ts
interface ServerFunctionsServerConfig {
  provideEvent?: <T>(event: ServerFunctionEvent, fn: () => T) => T;
  wrapInvocation?: WrapInvocationHook;
  collectFlightData?: CollectFlightDataHook;
  transformResult?(
    event: ServerFunctionEvent,
    result: unknown,
    context: {
      id: string;
      args: unknown[];
      request: Request;
      thrown?: boolean;
    }
  ): unknown | ResponseEnvelope | Promise<unknown | ResponseEnvelope>;
  transformFlightResult?(
    event: ServerFunctionEvent,
    outcome: { value: unknown; data: unknown },
    context: { id: string; args: unknown[]; request: Request }
  ): Response | undefined | Promise<Response | undefined>;
  transformDirectResult?(
    value: unknown,
    options: { id: string; args: unknown[]; event: ServerFunctionEvent }
  ): unknown;
  handleNoJS?:
    | ((
        result: unknown,
        request: Request,
        args: unknown[],
        thrown?: boolean
      ) => Response | Promise<Response>)
    | null;
  endpoint?: string;
  csrf?: boolean | ServerFunctionCSRFOptions;
  codec?: JSONCodecOptions;
  bodySizeLimit?: number;
  maxArguments?: number;
  secret?: string;
};
```

#### `provideEvent`

- **型:** `<T>(event: ServerFunctionEvent, fn: () => T) => T`

呼び出しのリクエストイベントスコープを確立します — 渡された関数は `event` が `getRequestEvent()` に見える状態で実行されます。`@solidjs/web/storage` の
`provideRequestEvent`（またはフレームワークの同等物）に接続してください。省略した場合、確立済みのリクエストスコープがグローバルに置く AsyncLocalStorage インスタンスにフォールバックします。

#### `wrapInvocation`

- **型:** `WrapInvocationHook`

すべてのサーバー関数実行を — HTTP ディスパッチと直接 SSR
呼び出しの両方を — 呼び出し識別情報が確立された状態でラップします（
`WrapInvocationHook` を参照）。フレームワークポリシーの呼び出しごとの継ぎ目です:
関数ごとのミドルウェア、認証、ロギング、エラーマッピング。リクエスト単位のオプションが HTTP ディスパッチではこれを上書きします。

#### `collectFlightData`

- **型:** `CollectFlightDataHook`

名前なしのシングルフライトフックです: オプトインした
呼び出しのレスポンスに折り込まれるデータペイロードを生成します（`CollectFlightDataHook` を参照）。
データ生成を所有する統合（ルーター）が一度だけ登録し、ハンドラー単位の `collectFlightData` オプションがそれを上書きします。他の統合はこのスロットを競うのではなく、
`registerFlightDataSource(id, hook)` を通じて追加的に貢献します。

#### `transformResult`

- **型:** `unknown | ResponseEnvelope | Promise<unknown | ResponseEnvelope>`

ハンドラーの `transformResult` のサーバー全体のデフォルトです（同じ
契約 — `HandleServerFunctionRequestOptions` を参照）。リクエスト単位のオプションが
これを上書きします。ここに登録すると、結果ポリシー（例: frames の
`frameTransformResult`）が、オプションなしで `handleServerFunctionRequest(request)` を呼ぶ汎用ディスパッチャー経由でも機能するようになります。

#### `transformFlightResult`

- **型:** `Response | undefined | Promise<Response | undefined>`

シングルフライト集約における `transformResult` の対応物です:
呼び出しの flight ペイロードがポリシーしか構築方法を知らないボディを必要とするとき
（frames の `frameTransformFlightResult` — 無効化されたエントリは
マークアップです）、これが `{ value, data }` の結果に対する先取権を得ます。
結果を運ぶには `Response` を返し（呼び出しのヘッダーとクッキーが
そこにコピーされます）、辞退して素の
シリアライズ済みエンベロープを維持するには `undefined` を返します。リクエスト単位のオプションがこれを上書きします。

#### `transformDirectResult`

- **型:** `unknown`

ドキュメント SSR 中の直接（同一サーバー）呼び出しに対する、`transformResult` のプロセス内ミラーです — 例: frames の `frameTransformDirectResult`。

#### `handleNoJS`

- **型:** `| ((
        result: unknown,
        request: Request,
        args: unknown[],
        thrown?: boolean
      ) => Response | Promise<Response>)
    | null`

クライアントランタイムなしで行われた呼び出しのためのサーバー全体のレスポンスビルダーです
（`HandleServerFunctionRequestOptions` の `handleNoJS` を参照）。リクエスト単位のオプションがこれを上書きします。`createNoJSHandler({ base })` を設定するとその慣例がブラウザのフォーム投稿だけでなくすべての非スクリプト呼び出しに適用され、独自のハンドラーを設定するとそれを置き換え、`null` を設定すると組み込みの慣例を無効にしてフォーム投稿に素のシリアライズ済みレスポンスで応答します。

#### `endpoint`

- **型:** `string`

HTTP ハンドラーが応答するマウントパスです。クライアント
設定と一致しなければなりません — id はその後のセグメントとして伝わり、それで始まらないパスのリクエストは呼び出しではなく、SSR されたリファレンスの `url`
（例: フォームの action）はそこから導出されます。アプリがベースパスから配信される場合はプレフィックスを付けてください（例: `` `${BASE_URL}_server` ``）。

#### `csrf`

- **型:** `boolean | ServerFunctionCSRFOptions`

HTTP サーバー関数呼び出しの同一オリジン保護です。デフォルトで
有効です。別の信頼できる層が
エンドポイントを保護している場合のみ `false` に設定してください。

#### `codec`

- **型:** `JSONCodecOptions`

引数のデコードと結果のエンコードのためのコーデックオプション（追加プラグインなど）です — クライアント側と一致させる必要があります。共有レイヤーに保存されるため、
`decodeResponse` からも見えます。`serializeErrorStacks` が省略された場合、
サーバー関数バウンダリはこのモジュールのコンパイル済み開発バリアントからデフォルトを得ます。

#### `bodySizeLimit`

- **型:** `number`

呼び出しの引数ペイロード — POST ボディ、
または `?args=` クエリエンコーディング — のバイト単位の上限です。ペイロードはディスパッチ前にバッファされデコードされるため、アプリケーションコードが
拒否する前にそのコストが支払われます。上限は前もって強制され、超過したリクエストはデコード前に `413` で拒否されます（#3115）。大きなアップロードを受け付ける関数では引き上げるか、`Infinity` を設定して上限をなくしてください。

#### `maxArguments`

- **型:** `number`

呼び出しが持てる引数の数の上限です。デコードされた
引数配列は関数呼び出しに展開されるため、無制限のリストは関数が何をするかに関わらず RangeError を引き起こします。
上限を超えたリクエストは `400` で拒否されます（#3115）。

#### `secret`

- **型:** `string`

デプロイシークレットです: デプロイごとに1つの値で、鍵を必要とする機能はここから各自の鍵を導出します
（ドメイン分離されているため、用途ごとの鍵は素材を共有しません）。現在この機能は1つです — no-JS フラッシュクッキー
（#3239）: フラッシュは送信されたフォーム入力 — ユーザーが入力したものなら何でも — を運ぶため、そのペイロードは常に AES-GCM で暗号化されます。平文で
通信に載ったりクッキージャーに置かれたりすることはありません。フォーム投稿後のレンダーを配信できるすべてのインスタンスがシークレットを共有しなければならないため（ロードバランサー配下では、インスタンスごとのシークレットは結果を静かに失います）、
ここには生成されたフォールバックがありません: これが設定されていない場合、シークレットは
Solid バンドラープラグインがサーバービルドに注入する値
（ビルドごとの新しい値）にフォールバックし、どちらもない場合は結果は
フラッシュされません — フォーム投稿はそれでも正常にリダイレクトし、開発ビルドは一度だけ警告します。

32 バイト以上の高エントロピーな値を使い、ソース管理から外してください:

```sh
node -e "console.log(crypto.randomBytes(32).toString('base64url'))"
```

取得されたクッキーはこの値に対するオフラインオラクルです。鍵導出はストレッチングを行います（PBKDF2-HMAC-SHA-256）が、推測のコストを上げるだけで、推測可能なシークレットを安全にはしません。これを復元できれば、すべてのフラッシュペイロードを読み、新しいものを偽造できます。パスフレーズ、アプリ名、その他の人が思いつくものでは不十分です。

ローテーション（またはプラグインの値での再デプロイ）を行うと、進行中のフラッシュは無効になります。これらは 60 秒のワンショットクッキーなので、次のレンダーは「フラッシュなし」を読みます。

### `WrapInvocationHook`

サーバー関数の実行をラップします — フレームワークポリシー（関数ごとのミドルウェア、認証、ロギング、エラー
マッピング）の呼び出しごとの継ぎ目です。呼び出し識別情報が確立された状態で、呼び出しのイベントスコープ内で呼ばれます: `getServerFunctionInvocation()` は
`run()` の前・実行中・後に応答します。`run()` の
結果を返す（または解決する）必要があります — それを置き換えると関数の結果が置き換わります。スローはハンドラーの通常のエラーエンコーディングに流れます。

コンテキストは呼び出しの識別情報（`id`、パース済み `args`）、その
`event`、および到達経路を保持します: `direct` はプロセス内 SSR 呼び出し
（`request` が存在しない）で `true`、HTTP ディスパッチで `false` です。直接経路では、ラッパーは同期関数に対して透過であり続けなければなりません — 非同期である必要がない限り、無条件の Promise ではなく `run()` の値を返してください。

```ts
type WrapInvocationHook = (
  run: () => unknown,
  context: {
    id: string;
    args: unknown[];
    event: ServerFunctionEvent;
    request?: Request;
    direct: boolean;
  }
) => unknown;
```
