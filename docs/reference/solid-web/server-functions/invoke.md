呼び出しスコープの `signal`、`keepalive`、`priority` オプションを付けてサーバー関数を呼び出します。

> 呼び出しスコープのオプションについては[メタデータとトランスポート](/docs/building-apps/server-functions/metadata-and-transport.md#configure-one-call)を参照してください。

```ts
function invoke<A extends readonly any[], R>(
  fn: (...args: A) => R,
  options: InvokeOptions,
  ...args: A

```

## 関連する型

### `InvokeOptions`

`invoke` の呼び出しごとの、呼び出しスコープのオプションです — 同じ関数の呼び出し間で変化し、宣言（`GET`、`withMeta`）や設定（`prepareRequest`）では表せないものです。サーバー上では呼び出しはプロセス内で行われます: `signal` は依然として呼び出し元を拒否しますが、トランスポートヒントは no-op です（存在しない通信を記述しているため）。

```ts
interface InvokeOptions {
  signal?: AbortSignal;
  keepalive?: boolean;
  priority?: "high" | "low" | "auto";
};
```

#### `signal`

- **型:** `AbortSignal`

呼び出しのライフサイクルです。中断すると、シグナルの理由で呼び出しを拒否し、リクエストをキャンセルします（サーバー側で `request.signal` が発火します）。
ライブソースのイテレーションは再接続をまたいで終了します。指定された場合、シグナルが通信を所有します — タイムアウトはこれを通じて合成されます（`AbortSignal.timeout`、`AbortSignal.any`）。

#### `keepalive`

- **型:** `boolean`

リクエストをページより長生きさせます — アンロード中（`pagehide`）の投げっぱなし呼び出しに使います。fetch の `keepalive` に対応し、ボディサイズの上限もそのまま含みます。

#### `priority`

- **型:** `"high" | "low" | "auto"`

Fetch の優先度ヒントです — 投機的プリフェッチか、操作によるフェッチかを示します。

### `ServerFunctionInvoker`

リファレンスの呼び出しチャネルで、`SERVER_FUNCTION_INVOKE` の下に格納されます:
呼び出しごとのオプションを適用して1回の呼び出しを実行します。宣言ラッパー（`GET`、`live`）はこれを機械的に転送します — 呼び出しの対応関係を 1:1 に保つためです。呼び出しを共有するラッパー（重複排除キャッシュ、マルチキャストチャネル）は、呼び出し元の中断が共有処理に何を意味するかをまず決めた上で、意図的にオプトインします — あるいは拒否し、`invoke` に指向エラーで応答させます。オプションは検証済みの状態で届きます — `invoke` は呼び出しスコープのキーのみを受け付けます。

```ts
type ServerFunctionInvoker<A extends readonly any[] = any[], R = any> = (
  args: A,
  options?: InvokeOptions
) => R;
```
