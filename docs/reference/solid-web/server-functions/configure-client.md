ブラウザのサーバー関数エンドポイント、コーデック、リクエスト準備、レスポンス統合を設定します。

## インポート

```ts
import { configureServerFunctionsClient } from "@solidjs/web/server-functions";
```

## 型シグネチャ

```ts
function configureServerFunctionsClient(config?: ServerFunctionsClientConfig): void;
```

## パラメータ

### `config`

- **型:** `ServerFunctionsClientConfig`
- 省略可

## 例

```ts
configureServerFunctionsClient({
	prepareRequest(init) {
		const headers = new Headers(init.headers);
		headers.set("authorization", `Bearer ${session.token()}`);
		return { ...init, headers };
	},
});
```

## 関連する型

### `PrepareRequestContext`

`prepareRequest` が送信する RequestInit とともに受け取るコンテキストです。

```ts
interface PrepareRequestContext {
  id: string;
  meta: ServerFunctionMetadata | undefined;
};
```

#### `id`

- **型:** `string`

呼び出される関数の、ビルド間で安定した ID。

#### `meta`

- **型:** `ServerFunctionMetadata | undefined`

参照の宣言メタデータ（例: `GET(fn)` 参照なら `method: "GET"`）。プレーンな参照は空のオブジェクトを持ちます。

### `PrepareRequestHook`

クライアント側のセッション動的トランスポートフックで、サーバー関数の fetch のたびに実行されます。トランスポートが使う RequestInit を返します（または変更して返します）— フックはトランスポートのヘッダーを含む最終的な init を見ます。想定するユースケースは、セッション中にローテーションし、すべての呼び出しに一律適用される動的クレデンシャル（OAuth ベアラートークン）です。サーバーのハンドラーフックのクライアント側版に相当します。チェーンではなく単一のフックです — 合成する場合はユーザーランドで関数をラップしてください。

```ts
type PrepareRequestHook = (
  init: RequestInit,
  context: PrepareRequestContext
) => RequestInit | Promise<RequestInit>;
```

### `ServerFunctionsClientConfig`

`configureServerFunctionsClient` のオプションです。

```ts
interface ServerFunctionsClientConfig {
  endpoint?: string;
  codec?: JSONCodecOptions;
  fetch?: ((address: string, init: RequestInit) => Response | Promise<Response>) | null;
  prepareRequest?: PrepareRequestHook;
  responseHandler?: {
    capture?(info: { id: string; meta: unknown }): unknown;
    handle(
      response: Response,
      ctx: { id: string; meta: unknown; args: unknown[]; context: unknown }
    ): unknown;
  };
  serializeArgs?(args: unknown[]): string | Promise<string>;
};
```

#### `endpoint`

- **型:** `string`

サーバーの HTTP ハンドラーが応答するマウントパスです。サーバー側の設定と一致させる必要があります — ID はこのパスの後のセグメントとして送られ、SSR された参照の `url`（フォームアクションなど）とクライアントの fetch はどちらもここから導出されます。アプリがベースパスから配信される場合はプレフィックスを付けます（例: `` `${BASE_URL}_server` ``）。

#### `codec`

- **型:** `JSONCodecOptions`

引数のエンコードと結果のデコードに使うコーデックオプション（追加プラグインなど）— サーバー側と一致させる必要があります。共有レイヤーに保持されるため、`decodeResponse` からも見えます。

#### `fetch`

- **型:** `((address: string, init: RequestInit) => Response | Promise<Response>) | null`

すべてのサーバー関数リクエストを送信します — リトライ、テレメトリ、テストダブル、アプリ独自のルートなどに使えます。常に `(address, init)` として呼び出され、address はグローバルの fetch が受け取るのと同様にドキュメントからの相対アドレスです。そのため `parseServerFunctionActionUrl` はテレメトリ用に ID を読み戻せます。`null` を渡すとグローバルに戻ります。

```ts
configureServerFunctionsClient({
  fetch: (address, init) => fetch(rewrite(address), init)
});
```

`init` はそのまま転送してください — 呼び出しの `signal` はそれに乗っており、落とすと呼び出し側の abort と、ライブソースの `break` が行うティアダウンの両方が無効になります。呼び出しは同一オリジンに保ってください。クロスオリジンの送信には `Sec-Fetch-Site: cross-site` が付き、ハンドラーのオリジンゲートに拒否されます。そしてピアが返したものを、読まずにそのまま返してください。

リトライするラッパーは、レスポンスがまったくなかったリクエストのみ再送信できます。レスポンスが完了したものを再生してはいけません。ボディの途中で途切れたレスポンスは実行済みかもしれず（ミューテーションは冪等ではありません）、ライブソースの再接続はランタイムの仕事です — 再生するとそれと競合します。

このラッパーが置き換えるのは、ランタイムが送信すると決めたリクエストの配送です。呼び出しとリクエストの対応関係自体は契約ではありません。

#### `prepareRequest`

- **型:** `PrepareRequestHook`

サーバー関数の fetch のたびに実行されます。トランスポートが使う RequestInit を返します（または変更して返します）。`context.meta` は参照の宣言メタデータ（例: method）です。セッション中に変化する横断的な関心事 — ベアラートークンやトレーシングヘッダーに使います:

```ts
configureServerFunctionsClient({
  prepareRequest(init) {
    return {
      ...init,
      headers: { ...init.headers, Authorization: `Bearer ${session.token()}` }
    };
  }
});
```

#### `responseHandler`

- **型:** `{
    capture?(info: { id: string; meta: unknown }): unknown;
    handle(
      response: Response,
      ctx: { id: string; meta: unknown; args: unknown[]; context: unknown }
    ): unknown;
  }`

レスポンス側の統合ポイント — ハンドラーの `transformResult` のクライアント側ミラーです。`handle(response, ctx)` はトランスポートがデコードする前にすべてのレスポンスを見ます。undefined 以外を返すと、その値で呼び出しが解決されます。`capture(info)` は呼び出し場所で同期的に（await の前に）実行され、その戻り値は `ctx.context` として届きます。これにより呼び出しごとの暗黙の状態（例: リアクティブオーナー）がレスポンス時まで生き残ります。標準的な実装は frame-transport の `createServerComponentHandler` を参照してください。

#### `serializeArgs`

- **型:** `string | Promise<string>`

JSON が忠実に運べない引数リストのエンコーダーです。JSON セーフな引数は常にプレーンな JSON で送られます（バンドルにコーデックは含まれません）。それ以外は、これを設定しない限りスローされます。rich-args エントリーの `enableRichArguments()` がインストールします — 独自のワイヤー形式を使う場合のみ直接設定してください。
