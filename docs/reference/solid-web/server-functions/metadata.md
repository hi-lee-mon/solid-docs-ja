## 関連する型

### `ServerFunction`

サーバー関数リファレンスの公開契約です — `"use server"` インポートが実行時にどちら側でも何になるかを表します: 非同期の呼び出し可能オブジェクトと、ビルド間で安定した識別情報です。

```ts
interface ServerFunction<A extends readonly any[] = any[], T = any> {
  (...args: A): Promise<T>;
  readonly id: string;
  readonly url: string;
};
```

#### `id`

- **型:** `string`

ビルド間で安定した関数 id です（クライアントビルドとサーバービルドで同一）。

#### `url`

- **型:** `string`

この関数のプレーン HTTP アドレスです — ランタイムなしで `<form action>` が POST する先です（`action={fn}` の背後にある統合がこれを読み取ります）。リファレンス自身の呼び出しが向かう先ではありません: それは `serverFunctionUrl(fn, ...args)` で、`GET()` リファレンスの場合はプリロードやフェッチに使う URL です。

### `ServerFunctionMetadata`

宣言ラッパー（`GET`、`withMeta`）を通じてサーバー関数リファレンスに付与される、宣言時に静的なメタデータです。`getServerFunctionMetadata` で読み取ります。ルーターや統合はプロパティの嗅ぎ分けではなくここから機能を検出し、`prepareRequest` はこれを `context.meta` として受け取ります。書き込みは `withMeta` を通じて行います — 後の書き込みは先のものに浅くマージされます。

```ts
interface ServerFunctionMetadata {
  readonly method?: "GET" | "POST";
  readonly name?: string;
  readonly [key: string]: unknown;
};
```

#### `method`

- **型:** `"GET" | "POST"`

宣言された HTTP メソッドです。宣言のないリファレンスは POST で呼び出します。

#### `name`

- **型:** `string`

関数の人間が読めるラベルで、開発ビルドがコンパイル済み関数のソース名から初期値を設定します（開発ツール — インスペクター、ログ向け）。開発専用です: 本番ビルドは name を出力しません。一意ではなく、識別キーでもありません — 識別には `id` を使ってください。デフォルトとして設定されるだけなので、明示的な `withMeta` の書き込みが優先されます。
