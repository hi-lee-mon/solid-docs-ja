SSR 中に、現在のリアクティブスコープの存続期間にわたって HTTP
レスポンスステータス（およびオプションのステータステキスト）を宣言します。
ステータスが決定される場所（404 ルート、エラーフォールバック）で、
コンポーネントまたはリアクティブスコープの本体にそのまま呼び出します。
クライアントビルドでは何もしません — レスポンスヘッドはとうに送信済みです。

命名に関する補足 — これはスコープに紐づく*宣言*であり、ミューテーションでは
ありません。「このリアクティブスコープが生きている間、レスポンスはこの
ステータスを持つ」という意味です。Solid は `set*` 動詞をイベント時の
ミューテーション用に予約しています。`createSignal`/`onCleanup` と同様に、
これはスコープ本体で呼び出され、スコープの破棄時に宣言が取り消されます。

撤回のセマンティクス（サーバー）: 書き込み時に以前の `event.response`
ステータスをスナップショットし、所有スコープが破棄されると復元します。
つまり、エラーになってステータスを宣言してから回復したバウンダリは、
ツリーの生き残った部分が正当に設定したステータスを上書きするのではなく、
自分の書き込みを撤回します。レスポンスヘッドが `committed`
（ヘッドが確定・送信済み — パイプされた `renderToStream` の
シェルフラッシュ、await されたものまたは `renderToString` の完了）
になると、書き込みと撤回は何もしなくなります。

## インポート

```ts
import { httpStatus } from "@solidjs/web";
```

## 型シグネチャ

```ts
function httpStatus(code: number, text?: string): void;
```

## パラメータ

### `code`

- **型:** `number`

HTTP ステータスコード。

### `text`

- **型:** `string`
- オプション

オプションのステータステキスト。

## 例

### 見つからないルートから 404 を返す

```tsx
function NotFound() {
	httpStatus(404);
	return <h1>Page not found</h1>;
}
```

### 失敗したレンダーを報告する

```tsx
<Errored
	fallback={(error) => {
		httpStatus(500);
		return <p>Something went wrong.</p>;
	}}
>
	<Page />
</Errored>
```

## 注意点

- 見つからないルートやエラーフォールバックなど、ステータスを決定するスコープで呼び出してください。ブラウザでは何もしません。
- 破棄されたスコープはそのステータスを撤回するため、回復したエラーバウンダリが 500 を残すことはありません。
- レスポンスヘッドが確定した後の書き込みは無視されます。
