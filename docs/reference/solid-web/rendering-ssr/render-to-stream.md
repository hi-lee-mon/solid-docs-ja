HTML レスポンスをストリーミングします。まず同期シェルをフラッシュし、
次に `<Loading>` バウンダリが確定するにつれて非同期に解決された
フラグメントを順次出力します。初回バイトまでの時間（TTFB）が重要な
ページに適しています。

Node の `Writable` や Web の `WritableStream` へパイプするための
`pipe`/`pipeTo`、`new Response(stream.readable)` 用の遅延
`readable` バイトストリームビューに加え、完了を待つための
thenable を持つオブジェクトを返します。
`await renderToStream(...)` は確定済みの HTML（レンダーの
完全解決文字列形式）で解決します。`pipe`、`pipeTo`、
`readable` はそれぞれレンダーを消費します —
3 つのうちちょうど 1 つを使ってください。

## インポート

```ts
import { renderToStream } from "@solidjs/web";
```

## 型シグネチャ

```ts
function renderToStream<T>(
  fn: () => T,
  options?: {
    nonce?: CSPNonce;
    renderId?: string;
    noScripts?: boolean;
    plugins?: any[];
    manifest?: AssetManifest | AssetResolver | AssetResolverFn;
    onCompleteShell?: (info: { write: (v: string) => void }) => void;
    onCompleteAll?: (info: { write: (v: string) => void }) => void;
    /** This render's server error hook, ahead of `configureServerErrors`' (see the server entry). */
    onError?: ServerErrorHook;
    /**
     * Embedded-render contract for hosts that own the document. When the
     * shell contains no `</head>`, everything head-bound at first flush
     * (resolved `useHead` winners, eager resources, tracked asset links,
     * inline styles) is delivered here as one HTML string — prelude first —
     * before the shell chunk is emitted, so the host can write its own
     * `<head>` ahead of piping the stream. Post-shell head updates flow
     * through the stream itself and apply in the browser. Not called when
     * the shell has a `</head>` (splicing is automatic then).
     */
    onHead?: (head: string) => void;
  }
): {
  /**
   * Awaiting the stream resolves with the complete HTML once every boundary
   * settles — the fully-settled-string form of the render. Render errors
   * route through `onError` and the promise resolves with whatever HTML the
   * render produced; it never rejects.
   */
  then<TResult1 = string, TResult2 = never>(
    onfulfilled?: ((html: string) => TResult1 | PromiseLike<TResult1>) | null,
    onrejected?: ((reason: any) => TResult2 | PromiseLike<TResult2>) | null
  ): Promise<TResult1 | TResult2>;
  pipe: (writable: { write: (v: string) => void; end: () => void }) => void;
  pipeTo: (writable: WritableStream) => Promise<void>;
  readonly readable: ReadableStream<Uint8Array>;
};
```

## パラメータ

### `fn`

- **型:** `() => T`

ルート JSX を返す関数。

### `options`

- **型:** `{ nonce?: CSPNonce; renderId?: string; noScripts?: boolean; plugins?: any[]; manifest?: AssetManifest | AssetResolver | AssetResolverFn; onCompleteShell?: (info: { write: (v: string) => void }) => void; onCompleteAll?: (info: { write: (v: string) => void }) => void; onError?: ServerErrorHook; onHead?: (head: string) => void; }`
- オプション

`renderToString` のオプションに加えて、`onCompleteShell` と `onCompleteAll` フック。

## 戻り値

`pipe`、`pipeTo`、`readable` を持つストリームオブジェクト。await すると完全に確定した HTML で解決します。

## 例

```tsx
import { renderToStream } from "@solidjs/web";

// Node:
renderToStream(() => <App />).pipe(res);

// Web (Workers / Deno):
return new Response(renderToStream(() => <App />).readable);

// Fully settled string:
const html = await renderToStream(() => <App />);
```

## 注意点

- `pipe`、`pipeTo`、`readable` はそれぞれレンダーを消費します。どれか 1 つだけを使うか、確定済み文字列を得るためにストリームを await してください。
- レンダーエラーは `onError` に送られます。await した Promise は決して拒否されません。

## 関連型

### `PreloadLink`

SSR アセットパイプラインが出力する明示的な `<link rel="preload">`。

`as` は HTML 標準が定めるプリロード宛先の集合そのものです。それ以外の
値は null に変換され、ブラウザはそのリンクを無視します。

`imagesrcset` の候補はインテグレーションによってすでに解決済みでなければ
なりません。それらはそのまま受け渡されます（相対候補はマニフェストの
ベースではなくドキュメント URL に対して解決されます）。候補が幅記述子を
使う場合は必ず `imagesizes` と組み合わせてください。これは仕様上
必須であり、これがないとソースサイズは `100vw` にフォールバックし、
プリロードが `<img>` が選択した画像を取りこぼす可能性があります。
`href` の省略は、ソースセット形式に対する仕様自身の推奨です。
それは `imagesrcset` をサポートしないブラウザにしか役立たず、
そこでは誤った候補をプリロードしてしまう可能性が高いからです。

```ts
type PreloadLink = PreloadLinkAttributes &
  (
    | {
        href: string;
        as: Exclude<JSX.HTMLPreloadAs, "image">;
        imagesrcset?: never;
        imagesizes?: never;
      }
    | {
        href: string;
        as: "image";
        imagesrcset?: string;
        imagesizes?: string;
      }
    | {
        href?: never;
        as: "image";
        imagesrcset: string;
        imagesizes?: string;
      }
  );
```
